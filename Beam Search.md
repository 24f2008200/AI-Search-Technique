This is an execution trace of Beam Search. Let us understand it step by step, using your trace.

The important idea behind Beam Search is:

> At every level of the search tree, expand the current candidates, evaluate their successors, and retain only the best \\(k\\) candidates. Discard the rest.

Unlike BFS, which retains every generated node, Beam Search limits the number of nodes explored.

## 1. Understanding the notation

Each node is represented as:

`(state, parent, score)`

For example:

`(01111, 11111, 4)`

means:

- `01111` – the current state.
- `11111` – the parent from which this state was generated.
- `4` – its evaluation score (heuristic value).

The lists have these meanings:

| Term       | Meaning                                                   |
| ---------- | --------------------------------------------------------- |
| OPEN       | Nodes selected for further expansion                      |
| CLOSED     | Nodes already expanded                                    |
| moveGen    | States generated by applying possible moves               |
| neighbours | Generated states associated with their parents and scores |
| pruned     | Candidates discarded by the selection process             |
| PATH       | Final solution path, if found                             |

From the trace, a higher score appears to be preferred.

## 5. What should you understand about Beam Search?

Compare Beam Search with BFS:

| BFS                                              | Beam Search                                |
| ------------------------------------------------ | ------------------------------------------ |
| Expands all eligible nodes at a level            | Expands only selected nodes                |
| Does not normally prune based on heuristic score | Prunes candidates based on heuristic score |
| Can consume considerable memory                  | Uses less memory                           |
| Can find a shortest path in an unweighted graph  | Does not guarantee the shortest path       |
| Does not require a heuristic                     | Requires an evaluation heuristic           |

## 6. The central intuition

Think of Beam Search as exploring a tree with a limited number of seats at each level.

- Generate all children.
- Rank them using the heuristic.
- Allow only the best two to continue.
- Discard the others permanently.
- Repeat.

The danger is that the best-looking candidates at the present level may not lead to the goal. A discarded candidate might have led to the solution.

That is why Beam Search is generally not complete and does not guarantee an optimal solution.
