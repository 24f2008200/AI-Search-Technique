## 1. Summary (one page)

* **Goal shift.** Earlier weeks asked *"find a path / solution quickly"* (DFS, BFS, DFID, Best-First, local search). Week 5 asks *"find the **optimal** (least-cost) solution, as fast as possible"*. Edges now carry **costs**, so the fewest-hops path need not be the cheapest path (bus-bus-bus is 4 moves but cheaper than a 2-move taxi).
* **Universal strategy** (unchanged since Week 3): *tag every candidate with an estimate of the cost of the complete solution; keep refining the best-looking candidate until the best solution is fully refined.* Different ways of estimating give different algorithms.
* **The optimality condition:** estimates must be **lower bounds** (never above the true cost). Then the first *fully refined* solution you pick is optimal. **Higher** lower bounds ⇒ **more pruning** ⇒ faster. Correctness needs only "lower bound"; performance wants "as high as possible".
* **Ladder of algorithms**

| Algorithm | Estimate used to rank candidates | Sense of direction? | Optimal? |
|---|---|---|---|
| British Museum | none (enumerate all) | – | Yes, but mindlessly expensive |
| Branch & Bound (BnB) | $g(n)$ — cost so far (i.e. $h\equiv0$) | No (explores a "ball" around start) | **Yes** |
| Dijkstra | $g(n)$, but **one** node per state with a parent pointer | No; finds paths to *all* nodes | **Yes** |
| Best-First | $h(n)$ only (looks ahead, ignores past) | Yes | No |
| **A\*** | $f(n)=g(n)+h(n)$ | **Yes** | **Yes if $h\le h^{\ast}$** (admissible) |

* **A\* = Dijkstra's bookkeeping (g-values, parent pointers, one copy of each node) + Best-First's heuristic.** Unlike Dijkstra, A\* may find a **better path to a node already on CLOSED**, so it needs **Propagate-Improvement**.
* **Admissibility conditions (all three):** (1) finite branching factor, (2) every edge cost $\ge\epsilon>0$ (a fixed positive constant — not merely "positive"), (3) $h(n)\le h^{\ast}(n)$ for all $n$ (**underestimate**). Overestimating can return a non-optimal path.

* **More informed ⇒ less search:**

if  $h_{1}(n) \le h_{2}(n) \le h^{\ast}(n)$  then every node expanded
by $A^{\ast}_2$ 

is also expanded by $A^{\ast}_{1}$.

## 2. Setting: from "any solution" to "optimal solution"

* Search spaces grow exponentially (10 neighbours ⇒ 10, 100, 1000, …), so we need ways to reach the goal faster; earlier lectures optimised the heuristic value itself (hill climbing, SA, GA, etc. — "evaluation / objective / fitness function" are the same idea).
* **Quality of solution** was *number of moves* (BFS gives the fewest). With real edge costs, the optimum may use more moves.
* **British Museum Procedure** (Patrick Winston's name): explore the *entire* search space and return the best. Guaranteed optimal; computationally mindless. Goal: **search as little as possible while still guaranteeing optimality.**
* **Refine-the-best strategy:** candidates are tagged with estimated cost of the **complete** solution; refine the best one *until the best solution is fully refined*. Two kinds of search space in which refinement happens:
  * **Solution (refinement) space** — abstract solutions are refined (TSP Branch & Bound, §3).
  * **State space** — a partial path is *extended* (BnB, Dijkstra, A\*, §4–6).
* **Stop condition (both):** a complete solution with known cost is available **and** no other candidate can have a smaller cost.
* **Pruning:** if a fully refined solution costs less than a partial candidate's *lower-bound* estimate, the partial candidate can never win ⇒ discard it.

## 3. Branch & Bound for TSP (refinement space)

### 3.1 Search space

* Root node = **set of all possible tours**.
* Each step **partitions** one set into two: tours **including** a chosen edge vs tours **excluding** it (e.g. `CB` vs `¬CB` for Chennai–Bangalore).
* Continue until a node describes **exactly one tour** (fully refined).
* Edge choice heuristic: pick the **cheapest** edge (e.g. Chennai–Bangalore, 360 km).
* Algorithm: **always refine the node with the lowest lower-bound estimate; terminate when the node picked is fully refined.**

### 3.2 Lower bound for a set of tours 🧪

For the **root** (all tours): for every city (row of the distance matrix) take the **two smallest positive entries**, add all rows, then **divide by 2** (each tour edge is counted from both of its end-cities; a tour on $n$ cities has $n$ edges but the sum counts $2n$ edge-ends).

$$LB(\text{all tours})=\frac12\sum_{i=1}^{n}\Bigl(\text{smallest}_i+\text{second smallest}_i\Bigr)$$

Lecture example (5 cities: Chennai, Goa, Mumbai, Delhi, Bangalore): $LB=4335$ km. Known distances quoted: C–G 800, C–B 360, C–M 1280, M–D 1540, M–B 1210, G–M 590, G–B 570.

* It is an **absolute lower bound** (no tour can be cheaper) but **loose**: it may count a city 3–4 times (Goa appeared four times), ignores Delhi's long edges entirely, and may use edge sets that aren't a tour.
* ✅ Property tested on 500 random instances: $LB\le$ optimal tour always.

### 3.3 Revising the estimate when edges are fixed

* **Include** edge $(a,b)$: replace the cheaper contribution in **both** rows $a$ and $b$ by the cost of $(a,b)$, then recompute $\tfrac12\sum$.
  * Force Chennai–Mumbai (1280): Chennai's 800 → 1280 (+480), Mumbai's 1210 → 1280 (+70): $4335+\tfrac{480+70}{2}=\mathbf{4610}$ ✅
  * Also force Mumbai–Bangalore (1210): Mumbai's 590 → 1210 (+620), Bangalore's 570 → 1210 (+640): $4610+\tfrac{620+640}{2}=\mathbf{5240}$ ✅
* **Exclude** edge: it may not be counted; use the next-cheapest entry instead (estimate goes **up**).
* **Reasoning that tightens bounds** (costs extra work ⇒ *trade-off between estimation effort and amount of search*):
  * A city can have **only two** tour edges ⇒ never count a third.
  * Edges that would close a **premature sub-tour** (Chennai–Mumbai + Mumbai–Bangalore ⇒ Chennai–Bangalore forbidden) must be removed from the estimate.
  * 🔎 In code you must either do this reasoning or just keep exploring (the professor noted a programmer needs the "little bit of extra reasoning", otherwise the tree is larger).

### 3.4 The worked run (lecture numbers)

| Node (set of tours) | Lower-bound estimate |
|---|---|
| root $S_0$ → include `CB` | 4335 (unchanged: `CB` already in the bound) |
| root → exclude `CB` | **5220** |
| `CB` & include `BG` | 4575 |
| `CB` & exclude `BG` | **4770** |
| `CB`,`BG`, +`GM` / ¬`GM` | both **fully refined** (only one completion each): costs **5250** and 5830 (🔎 which node has which cost is inferred) |
| `CB`,¬`BG`, +`GM`, then ±`GD` | one fully refined tour costing **5724** |
| node with estimate 5220 | refined further; every child ≥ the best complete tour |

* Final answer: **Chennai → Bangalore → Goa → Mumbai → Delhi → Chennai, cost 5250 km.**
* It terminates because the best open node is a **fully refined** tour whose cost is ≤ every other lower bound.
* Note the **negation sign** (`¬XY`) only says "do not use this edge"; the tour is read off from the *included* edges once fully refined (all $n$ edges are then determined).
* ⚠️ Observations: nodes with *higher* estimates are picked later and may never be picked; the weakest lower bound is $0$ ("blindly explore everything"); the more accurate, the more pruning.

## 4. Branch & Bound for state-space search

### 4.1 Idea

* Search space = **partial paths** from $S$; each is tagged with **actual cost so far** $g$ — *no lookahead* (the estimate of the total cost is just the cost of the partial path, i.e. $h\equiv0$, a trivially valid lower bound).
* **Expand the cheapest partial path** each iteration; stop when a **path to the goal** is the cheapest on OPEN.
* Compare: DFS dives deepest; BFS keeps *shallowest* first (fewest hops); **BnB keeps the *cheapest* first** (the cost-weighted analogue of BFS); DFID simulated BFS; heuristic search looks only forward.

### 4.2 Algorithm (📎 Week 5 sheet) 🧪

```text
BnB(S)
1 OPEN ← (S : [], 0) : []                 ← use a priority queue; items are (path, g)
2 while OPEN is not empty
3     (path, g) ← head OPEN
4     N ← head path                        ← the LAST node of the partial path is at the head
5     if GoalTest(N) = TRUE
6         return reverse path
7     else newPaths ← empty list
8         for each M in MoveGen(N)
9             newPaths ← (M : path, g + k(N,M)) : newPaths      ← each new path is consed in FRONT
10        OPEN ← sort_g ( newPaths ++ tail OPEN )
11 return empty list
```

* Paths are stored **reversed** (newest node first), hence `reverse path` at the end.
* Line 9 *conses* each new path onto `newPaths`, so `newPaths` ends up in **reverse MoveGen order**; then `sort_g` orders by $g$. ⚠️ With ties, apply the course tie-break (alphabetical by node label) — check what the question states.
* `BnB-2` 📎 is a variation that prevents cyclic expansions like $S,\dots,A,\dots,S,\dots,A,\dots$.
* **No loop checking in the basic version** (a lecture choice, because loop checking has costs — see DFID): the tree grows with paths like $S\!-\!B\!-\!S$ (cost 6), but cost keeps rising so they never win.
* Simple improvement: **exclude any path in which a node repeats.**

### 4.3 Lecture example

State graph (costs): $S\!\to\!A\,(6),\ B\,(3),\ C\,(8)$; $B\!\to\!A$ gives a cheaper route to $A$ with total $5$; $D$ reached via $S\!-\!B\!-\!D$ at total $7$ (edge $B$–$D$ = 4); $C\!-\!G=8$; optimal route $S\!-\!B\!-\!D\!-\!G$ with cost **13**.

* Expand $S$: $\{A{:}6,\ B{:}3,\ C{:}8\}$ → cheapest $B$.
* Expand $B$: $S{:}6$ (cycle), $A{:}5$ (**better than the direct 6**), $D{:}7$.
* Same node shows up many times via different paths (e.g. $D$ with cost 11 via $S\!-\!B\!-\!A\!-\!B\!-\!D$) — wasted work; the cheapest way to $D$ is $S\!-\!B\!-\!D=7$.
* Eventually $G$ is picked with cost 13 (the route via $C$ costs $8+8=16$); **every path cheaper than 13 is explored first**.

### 4.4 Properties

* **Optimal** (extends the cheapest path ⇒ stays "as close to the source as possible" like BFS).
* **No sense of direction**: explores a ring around the start. Lecture metaphor: BnB from IIT Madras to the Shore Temple, Mahabalipuram, **explores all of Chennai first** before heading south.
* Keeps **all distinct paths as separate nodes** ⇒ the same state is expanded again and again ⇒ big search tree. Fix: Dijkstra.

## 5. Dijkstra's algorithm

* Dijkstra (1959): shortest paths from a **source to all** nodes. Our task is one particular goal, so we stop at the goal ("pick it").
* Keep **only one copy of each node** with the best-known cost and a **parent pointer**; instead of many paths, you *modify the graph*.

```text
Dijkstra (course terminology)
 all nodes: cost ← ∞, colour ← white;   cost(S) ← 0
 repeat
    pick the CHEAPEST WHITE node n and colour it BLACK      (black ≡ CLOSED: its best path is final)
    for each neighbour m of n   (relax):
        if cost(n) + k(n,m) < cost(m):  cost(m) ← cost(n)+k(n,m);  parent(m) ← n   (update the back-pointer)
```

**Trace on the BnB example** (order of colouring black): $S$, $B(3)$, $A(5)$ [updated: parent changes from $S$ to $B$], $D(7)$, $C(8)$, $E$, finally $G$. When $G$ is first *generated* via $D$ (cost 13) it is **not** picked yet, because $C(8)$ is cheaper and still white; routes via $C$ cost $16$ so nothing changes. Result: same path/cost as BnB (13), found by modifying one graph rather than growing a huge tree.

**Why Dijkstra never needs "reopening":** when it blackens a node, its **cheapest path is already final** (every other open node costs at least as much and edge costs are non-negative).

## 6. Algorithm A-star

* Authors: **Hart, Nilsson and Raphael (1968)**, Stanford Research Institute (SRI). An **extension of Dijkstra** that uses a **heuristic** because we want one goal, not all nodes.
* Combines: **BnB/Dijkstra's past cost** $g$ + **Best-First's future estimate** $h$.

$$f(n)=g(n)+h(n)$$

* $g(n)$ = actual cost of the best path *found so far* from $S$ to $n$ (as in BnB/Dijkstra)
* $h(n)$ = estimated cost from $n$ to the goal (static function, as in Best-First)
* $f(n)$ = estimated cost of the **complete solution passing through $n$**

### 6.1 Algorithm (📎 Week 5 sheet; Baskaran's Dijkstra-style version) 🧪

```text
A*(S)
 1 default value of g for every node is +∞
 2 parent(S) ← null
 3 g(S) ← 0
 4 f(S) ← g(S) + h(S)
 5 OPEN ← S : []
 6 CLOSED ← empty list
 7 while OPEN is not empty
 8     N ← remove node with lowest f value from OPEN
 9     add N to CLOSED                                   ← BEFORE the goal test
10     if Goal-Test(N) = true
11         return Reconstruct-Path(N)                    ← follows parent pointers (no node pairs / CLOSED lookup)
12     for each M in Move-Gen(N)
13         if g(M) > g(N) + k(N,M)                       ← strictly better path to M found
14             parent(M) ← N
15             g(M) ← g(N) + k(N,M)
16             f(M) ← g(M) + h(M)
17             if M is in OPEN
18                 continue                              ← case 2
19             else if M is in CLOSED
20                 Propagate-Improvement(M)              ← case 3 (new in A*)
21             else add M to OPEN                        ← case 1: M is new
22 return empty list

Propagate-Improvement(M)
23 for each X in Move-Gen(M)
24     if g(X) > g(M) + k(M,X)
25         parent(X) ← M
26         g(X) ← g(M) + k(M,X)
27         f(X) ← g(X) + h(X)
28         if X is in CLOSED
29             Propagate-Improvement(X)                  ← recurse down through closed nodes
30 return
```

### 6.2 The three cases for a neighbour $M$ of the expanded node $N$ 🧪

| Case | Situation | Action |
|---|---|---|
| 1 | $M$ is **new** (never generated; $g=\infty$) | set parent, $g$, $f$; **add to OPEN** |
| 2 | $M$ already on **OPEN**, but a cheaper path found | update $g$, $f$, parent; keep it on OPEN (`continue`) |
| 3 | $M$ on **CLOSED**, cheaper path found | update $g$, $f$, parent, then **Propagate-Improvement** to its descendants |

* Textbooks list the three cases explicitly; the sheet **encodes them in one block** (the `if g(M) > g(N)+k(N,M)` gate, then OPEN/CLOSED/new).
* ⚠️ **If the new path is not strictly cheaper (`g(M) > ...` false) nothing happens** — no update, no re-adding.
* **Case 3 never happens in Dijkstra** (a black node's path is already optimal). It **can** happen in A\* because $h$ is only an *estimate*: a node may be picked from OPEN and closed *before* its best path is known.
* Only **one copy of every node**; no node pairs are kept (parent pointers instead).

### 6.3 Propagate-Improvement example (lecture numbers)

Node $N$ with $g=55$ is picked from OPEN; its neighbours show all three cases:

| Neighbour | Before | New candidate $g$ | Result |
|---|---|---|---|
| new node | – | $55+7=62$ | case 1: added to OPEN with $g=62$ |
| node on OPEN | $g=70$ (via the node with $g=50$) | $g=60$ via $N$ | case 2: parent redirected to $N$, $g$ and $f$ lowered |
| node on CLOSED | $g=60$ | $55+2=57$ | case 3: parent updated; **improvement of 3 is propagated** to its closed descendants, each with a smaller $g$ and a revised parent |

The improvement of $60\to57$ ($\Delta g=3$) propagates down the chain of already-closed children.

## 7. A-star in action (worked example)

**Problem:** nodes sit on a grid with spacing 10 units; start $I$, goal $W$; an imaginary river can be crossed at only **three bridges**; edges carry costs. Heuristic: **Manhattan distance** (the lecturer encourages using it in exams — no square roots). $h(I)=100$ (10 grid steps $\times$ 10), $h(W)=0$.

| | Best-First | **A\*** |
|---|---|---|
| Ranks by | $h$ only | $f=g+h$ |
| Nodes inspected | **8** | **14** |
| Solution cost | **195** (43+64+22+33+12+21) | **148** (optimal) |
| Behaviour | rushes straight to the river and takes whichever bridge looks closest | explores "back and forth": looks **back** (g) and **forward** (h) |

**A\* trace highlights** (f-values in order of expansion): $f(I)=100$ → child with $g=21$, $h=80$ → $101$ (cheapest) → child $90+12=102$ (Best-First would have taken the node with $h=70$, but its $f=70+(12+21)=103$) → $104$ → back to $103$ → … $122$, $126$, $142$, $143$ → eventually $146$, $147$, and finally goal with $f=148$ ($146$ came from $h=20$ plus path costs $41+21+21+22+21$; the goal's $148$ was picked last because $147<148$ was expanded first).

Take-aways:

* A\* **may expand "wrong-direction" nodes** because a long edge made the greedy-looking route expensive.
* It **keeps the best path to each node** (e.g. a node first reached via a 104-cost path later gets a cheaper parent).
* Doing **Dijkstra** on the same graph yields the same optimal path (lecture exercise), but A\* uses direction to look at fewer nodes in typical cases.
* The graph is **implicit** — generated on the fly by `MoveGen`; A\* only builds what it visits.

## 8. Admissibility of A-star

**Definition.** A search algorithm is **admissible** if it is *guaranteed to return an optimal solution whenever a solution exists*. The "$\star$" in A\* (vs plain "A") signals admissibility.

### 8.1 Optimal quantities (analysis only — not known to the algorithm)

| Symbol | Meaning |
|---|---|
| $g^{\ast}(n)$ | optimal cost from $S$ to $n$ |
| $h^{\ast}(n)$ | optimal cost from $n$ to the goal |
| $f^{\ast}(n)=g^{\ast}(n)+h^{\ast}(n)$ | cost of the optimal path from $S$ to goal **passing through $n$** |
| $f^{\ast}(S)=h^{\ast}(S)$ | cost of the optimal solution (denoted $f^{\ast}$ in the proof) |

$$g^{\ast}(n)\le g(n)\quad\text{always (the algorithm may not yet have found the optimal path to }n)$$

### 8.2 Why can A\* pick a node without its best path?

Dijkstra picks the cheapest white node, so its path is final. In A\*, $f$ includes an *estimate* $h$; a node may be picked while a cheaper path to it is still hidden behind OPEN nodes ⇒ **case 3**. We need a condition on $h$ that still guarantees an optimal answer.

### 8.3 What should $h$ be like?

* $h\equiv0$ ⇒ A\* becomes **Branch & Bound** (optimal but blind).
* $h=h^{\ast}$ would be perfect but does not exist in practice.
* So choose **either** $h\le h^{\ast}$ (**underestimate**) **or** $h\ge h^{\ast}$ (**overestimate**).

**Decisive example** (✅ reproduced in code). One step from the goal, two open nodes $P$ and $Q$, both with $g=100$. True remaining costs: $h^{\ast}(P)=30,\ h^{\ast}(Q)=40$ ⇒ optimum $=100+30=130$ through $P$. Both heuristics *mis-rank* the nodes (think $Q$ is closer):

| | $h(P)$ | $h(Q)$ | $f(P)$ | $f(Q)$ | Run | Result |
|---|---|---|---|---|---|---|
| **Overestimate** $h_1$ | 60 | 50 | 160 | 150 | expand $Q$ ⇒ $G$ with $f=100+40=140$; $140<160$ ⇒ **pick $G$ now** | **140 — not optimal** ✗ |
| **Underestimate** $h_2$ | 20 | 15 | 120 | 115 | expand $Q$ ⇒ $G$ with $f=140$; but $P$ has $f=120<140$ ⇒ **expand $P$** first | **130 — optimal** ✓ |

Reason: when $G$ is generated, $h(G)=0$ is exact; an underestimated competitor still looks cheaper than the false goal and is expanded, whereas an overestimated competitor looks *too* expensive and gets ignored forever.

### 8.4 Conditions for admissibility 🧪

A\* is admissible if **all three** hold:

1. **Finite branching factor** (otherwise you can't even generate the neighbours). The graph itself **may be infinite**. (Only methods like simulated annealing work with infinite branching, because they sample one random neighbour.)
2. **Every edge cost $\ge\epsilon>0$** for a fixed constant $\epsilon$. ⚠️ "Positive" alone is not enough: the infinite path with costs $1+\tfrac12+\tfrac14+\cdots=2$ has *finite total cost*, so the algorithm could get stuck on it. (Counter-example credited by the lecturer to a student, Arvind Narayan.)
3. **$h(n)\le h^{\ast}(n)$ for all $n$** (the heuristic **underestimates** — is *admissible*).

## 9. Proof of admissibility (lemmas and theorems)

Assume the three conditions. Let $f^{\ast}$ denote the optimal cost $f^{\ast}(S)$.

**Lemma 1 — Termination on finite graphs.** Each cycle moves one node from OPEN to CLOSED, and OPEN holds **one copy** of each node ⇒ finitely many cycles. It reports a path if one exists, else correctly returns "none" (searching the whole connected component of $S$ if necessary).

**Lemma 2 — OPEN always contains a node $n'$ on an optimal path with $f(n')\le f^{\ast}$.**

* Optimal path: $S,n_1,n_2,\dots,G$. Initially $S$ is on OPEN. Whenever a node of the path is removed, its successor on the path is added (and if it's $G$, the algorithm has already stopped). So there is always some path-node $n'$ on OPEN.
* Since $n'$ is on the optimal path, $g(n')=g^{\ast}(n')$. Then

$$f(n')=g(n')+h(n')=g^{\ast}(n')+h(n')\;\le\;g^{\ast}(n')+h^{\ast}(n')=f^{\ast}(n')=f^{\ast}(S)=f^{\ast}$$

  The "$\le$" is exactly the **underestimating** condition. ∎

**Lemma 3 — Completeness even for infinite graphs.** Each extension adds at least $\epsilon$ to $g$, and the branching factor is finite ⇒ only **finitely many** partial paths have $f<f^{\ast}$ (cost grows by $\ge\epsilon$ per step and each node has finitely many children). After those are exhausted the goal gets picked. So A\* finds a path whenever one exists.

**Theorem 4 — A\* returns an optimal path.** (Proof by contradiction.) Suppose it terminates by picking a goal $G'$ with $g(G')>f^{\ast}$. At that moment Lemma 2 gives a node $n'$ on OPEN with $f(n')\le f^{\ast}<g(G')=f(G')$. A\* would have picked $n'$ (lower $f$) rather than $G'$ — contradiction. ∎

**Lemma 5 — Every node expanded by A\* has $f(n)\le f^{\ast}$.** A\* picked $n$ in preference to the Lemma-2 node $n'$, so $f(n)\le f(n')\le f^{\ast}$ (transitivity). Consequently **A\* never expands a node with $f>f^{\ast}$**, and expands *all* nodes with $f<f^{\ast}$ (needed for the next theorem).

**Theorem 6 — More informed heuristic ⇒ smaller (or equal) search space.**

* Let $A_1^{\ast}$ and $A_2^{\ast}$ be admissible with heuristics $h_1,h_2$ and **$h_2(n)\ge h_1(n)$ for all $n$** ($h_2$ is *more informed*: $0\le h_1\le h_2\le h^{\ast}$, closer to $h^{\ast}$).
* **Claim:** $\forall n$: if $A_2^{\ast}$ expands $n$ then $A_1^{\ast}$ also expands $n$ ⇒ search space of $A_2^{\ast}\subseteq$ that of $A_1^{\ast}$.
* **Induction on depth.** *Base:* both expand $S$. *Hypothesis:* true for all nodes up to depth $K$. *Step:* assume (for contradiction) a node $L$ at depth $K+1$ is expanded by $A_2^{\ast}$ but **not** by $A_1^{\ast}$.
  1. $A_2^{\ast}$ expanded $L$ ⇒ by Lemma 5, $f_2(L)=g_2(L)+h_2(L)\le f^{\ast}$, i.e.

$$h_2(L)\;\le\; f^{\ast}-g_2(L)\qquad\text{(1)}$$

  2. $A_1^{\ast}$ terminated without expanding $L$ ⇒ $f_1(L)\ge f^{\ast}$. Also by the hypothesis $A_1^{\ast}$ has seen at least every path $A_2^{\ast}$ saw (parent of $L$ is at depth $K$), so $g_1(L)\le g_2(L)$. Hence

$$f^{\ast}\;\le\; g_1(L)+h_1(L)\;\le\; g_2(L)+h_1(L)\;\;\Longrightarrow\;\; f^{\ast}-g_2(L)\;\le\; h_1(L)\qquad\text{(2)}$$

  3. (1) and (2) give $h_2(L)\le h_1(L)$, contradicting $h_2>h_1$ (strictly more informed). ∎
* **Conclusion:** both find the optimum, but the one with the **higher (closer to $h^{\ast}$) admissible heuristic expands fewer nodes**. As $h\to h^{\ast}$ the search shrinks toward the optimal path; with $h=0$ (BnB) it is the largest.
* ⚠️ Nuance (🔎): the contradiction uses *strict* superiority at the node $L$; with merely $h_2\ge h_1$ the safe statement is "$A_2^{\ast}$ expands no more nodes than $A_1^{\ast}$ *when ties are broken consistently*".

The lecturer closes by noting the next topic: **variations of A\*** (leaner/meaner versions needing less time or space, even at the cost of admissibility) — see WA\* and SMGS in the Week 5–6 sheet (📎 covered in the earlier notes, §14).

| | **BnB** | **Dijkstra** | **Best-First** | **A\*** |
|---|---|---|---|---|
| Ranking value | $g$ | $g$ | $h$ | $f=g+h$ |
| Copies of a state | many (one per path) | **one** + parent pointer | one (pairs) | **one** + parent pointer |
| Sense of direction | none | none | strong (greedy) | strong |

## 12. Quiz-preparation tips

### Procedure and node order

1. **A\* step:** remove the node with the **lowest $f$** from OPEN → **add it to CLOSED** → goal test → generate neighbours. Goal test is on the *removed* node, not on generation (the example's $G$ at $f=148$ was generated early but picked last).
2. **Update rule is strict:** only if $g(N)+k(N,M)<g(M)$. Equal cost does **not** change parents.
3. **Parents are pointers**, not node pairs; reconstruct by following back-pointers from the goal.
4. **Case 3 (node on CLOSED):** update, then **Propagate-Improvement** through *its neighbours*; recurse only into neighbours that were already **CLOSED**; neighbours on OPEN just get new $g,f,$ parent.
5. **Ties in $f$:** apply the course rule (alphabetical by node label) unless the question gives another rule 🔎 (stated for cost-based algorithms in the Week 3 sheet).
6. **BnB:** OPEN holds `(path, g)`; head of `path` is the current node; paths are **cons-ed** so printed paths read **backwards** (end node first) until the final `reverse path`.
7. **Dijkstra:** colour **cheapest white** node black; relax neighbours; *replace* parent pointers when a cheaper path is found; a black node is final.
8. **Heuristics in exams:** use **Manhattan distance** on grids (lecturer's advice) and read the cost scale (each grid step is 10 in the example).

### Concepts

* BnB ≡ A\* with $h=0$; Dijkstra ≡ BnB with one copy/node; A\* ≡ Dijkstra + $h$.
* **Underestimation ⇒ optimal; overestimation ⇒ may stop too early** (the $P/Q$ example).
* **Higher lower bound ⇒ better pruning** — but only *valid* while it stays $\le$ the true cost.
* A\* explores **more** nodes than Best-First in the example (14 vs 8) but returns a **cheaper** path (148 vs 195).
* **Which nodes does A\* expand?** All with $f<f^{\ast}$, some with $f=f^{\ast}$, **none** with $f>f^{\ast}$.
* **Informed vs admissible are different words:** *admissible* = never overestimates; *more informed* = larger (closer to $h^{\ast}$) while staying admissible.

### Frequent traps ⚠️

* Writing "edge cost $>0$" instead of "$\ge\epsilon>0$" in admissibility conditions.
* Saying A\* needs $h$ *exact*; it needs only $h\le h^{\ast}$.
* Thinking Dijkstra can reopen nodes (it can't) or that A\* never does (it can).
* Forgetting to **divide by 2** in the TSP lower bound.
* Counting a city's third edge or a sub-tour edge in the TSP estimate after edges are forced.
* In Lemma 2, writing $g(n')=g^{\ast}(n')$ for *any* open node — only for the optimal-path node.
* Picking the goal as soon as it is *generated* instead of when it is the lowest-$f$ node on OPEN.

## 1. Summary (one page)

* **Theme:** A\* is optimal (admissible) but needs **exponential time and space** unless $h$ is near-perfect. Week 6 studies variations that **trade something for something else**: speed for optimality (WA\*), or **time for space** while staying admissible (IDA\*, RBFS, frontier search, SMGS, beam-stack search).
* **Weighted A\*:** $f(n)=g(n)+w\cdot h(n)$. $w=0$ ⇒ Branch & Bound; $w=1$ ⇒ A\*; $w\to\infty$ ⇒ Best-First. Larger $w$ ⇒ **fewer nodes** but admissibility is lost once $w\,h$ can exceed $h^{\ast}$ (example: 9 nodes, cost 153 vs A\* 14 nodes, cost 148).
* **Monotone (consistency) condition:** $h(m)-h(n)\le k(m,n)$ for every edge $m\to n$ (the heuristic underestimates the cost of **each edge**). Consequences:
  1. $f$ is **non-decreasing** along any path;
  2. A\* has found the **optimal path to every node it expands**: $g(n)=g^{\ast}(n)$ — like Dijkstra;
  3. **No Case 3** (no reopening of CLOSED nodes, no Propagate-Improvement);
  4. CLOSED may be **pruned** (needed only to avoid leaking back, and to rebuild the path).
* **Motivating problem — sequence alignment (DNA):** grid of $(N+1)(M+1)$ nodes; **OPEN grows linearly, CLOSED grows quadratically** ⇒ CLOSED is the memory bottleneck.
* **Pruning CLOSED:** *Frontier Search* (Korf & Zhang 2000: keep OPEN + "barred" lists + relay layer; **Divide-and-Conquer Frontier Search**, time ×$d$), *SMGS* (Zhou & Hansen 2003: boundary/kernel nodes, delete kernel, memory-aware).
* **Pruning OPEN:** *Beam search with $f$-values* (space $w\cdot d$, not admissible), upper bound $U$ from a beam run ⇒ prune $f>U$; *Breadth-First Heuristic Search* (BFS inside $f\le U$, admissible), *Divide-and-Conquer BFHS*, *D&C Beam Search* (3 layers, $O(1)$, inadmissible), *Beam Stack Search* (beam + backtracking with $(f_{\min},f_{\max})$ per level, admissible), *D&C Beam Stack Search* ($O(1)$ space, regenerates from start).
* **Linear-space A\* family (Korf):** **IDA\*** = DFID with an **$f$-bound** (next bound = smallest $f$ that exceeded the old one; repeated work, same nodes as A\*); **RBFS** = best-first with **rollback** and **backed-up $f$ values** (remembers the second-best; can thrash).

## 3. Weighted A-star (WA-star)

### 3.1 Definition 🧪

$$f(n)=g(n)+w\cdot h(n)\qquad (w\ge 0)$$

* $g$ = **pull toward the source** (look back); $h$ = **push toward the goal** (look forward). $w$ sets the relative influence of $h$.
* 📎 Algorithm: take A\* and change two lines: line 16 `f(M) ← g(M) + w ∗ h(M)` and line 27 (inside Propagate-Improvement) `f(X) ← g(X) + w ∗ h(X)`. Everything else (parent pointers, three cases, CLOSED) is unchanged.

| $w$ | $f(n)$ | Algorithm |
|---|---|---|
| $0$ | $g(n)$ | **Branch & Bound** (only pull to source) |
| $1$ | $g+h$ | **A\*** |
| $2$ | $g+2h$ | **WA\*** (example) |
| $\to\infty$ | $\approx h$ ($g\to0$ in relative terms) | **Best-First Search** |

### 3.2 Two-path illustration (lecture)

Two paths from start to goal of **equal cost 108** (horizontal segments of 12, diagonals of 24 and 36). Manhattan $h$: top path nodes $60,50,40,30,\dots$; the bottom path starts at $70$.

| First nodes | $g$ | $h$ | A\* $f=g+h$ | WA\* ($w=2$) $f=g+2h$ |
|---|---|---|---|---|
| top | 36 | 60 | **96** | **156** |
| bottom | 24 | 70 | **94** | **164** |

* A\* picks the **bottom** node first (94 < 96) and then keeps alternating between both paths (f 96, 98, …) — conservative, like B&B.
* WA\* picks the **top** (156 < 164); its $f$ then drops quickly (148, 140, 132…) so it **never looks at the bottom path**. Best-First (looks at $h$ only: 60 vs 70) behaves the same.
* Conservative: **B&B, A\***; goal-focused: **Best-First, WA\***.

### 3.3 Four algorithms on the grid example (same graph as Week 5)

| Algorithm | Weight | Nodes inspected (CLOSED) | Path cost | Optimal? |
|---|---|---|---|---|
| Branch & Bound | $w=0$ | **23** (whole graph) | **148** | Yes |
| A\* | $w=1$ | **14** (19 generated) | **148** | Yes |
| WA\* | $w=2$ | **9** | **153** | **No** |
| Best-First | $w\to\infty$ | **8** | **195** | No |

* Lecture quirk: WA\* "generated 70" nodes is what the lecturer states; Best-First's cost is stated as 195 (once as "193" — treat 195 as correct, it equals 43+64+22+33+12+21).
* **As $w$ grows, the explored space shrinks**, until $w\,h$ overestimates $h^{\ast}$ and optimality is lost.

### 3.4 Why WA\* is not admissible 🧪

Admissibility requires the **heuristic component** to underestimate: $w\,h(n)\le h^{\ast}(n)$. For $w=2$ this is not guaranteed ($2h$ may exceed $h^{\ast}$), exactly like the over-estimating $P/Q$ example of Week 5. (🔎 Standard result, not stated in the lecture: for $w\ge1$ and admissible $h$, the returned cost is at most $w\times$ optimal.)

### 3.5 Behaviour of $f$ values

* **A\*** (with the lecture's graphs): $f$ **increases** towards the goal: 100 → 101 → 143 → 144 → 145 → 146 → … → **148** at the goal. Reason: $g$ rises with true cost, while $h$ underestimates and its influence shrinks to 0 at the goal, so $f$ becomes more and more accurate. Every expanded node has $f\le f^{\ast}=148$.
* **WA\* ($w=2$):** $f$ **decreases** towards the goal (start 200, then 192, 184, a bump up to 206, then 190, … 153) because the inflated $h$ shrinks faster than $g$ grows.
* In WA\*, nodes **can be found with a better path after being closed**: a node got $f=226$, then later $184$ ⇒ **case 3 occurs** (needs Propagate-Improvement). In A\* with a **monotone** $h$ this never happens (§4).
* Student question (open): *a variable weight $w(h)$?* The professor: interesting exercise, not known.

## 4. The monotone (consistency) condition

### 4.1 Definition 🧪

For every node $m$ and its successor $n$ (any pair of nodes joined by an edge):

$$h(m)-h(n)\;\le\;k(m,n)$$

* "The heuristic **underestimates the cost of each edge**": the drop in $h$ across an edge never exceeds the edge cost (a triangle inequality; $h(m)\le k(m,n)+h(n)$).
* Lecture's grid: every square is 10 km, $h$ = Manhattan distance, edge costs are chosen $\ge$ Manhattan length of the edge. Checks: $H$ (120) and $O$ (100): difference $20<23$ (edge cost); $E$ (120) and $B$ (110): $10<33$; $U$/$S$: $20<21$ — holds in both directions.
* ✅ In code: for 200 random grid graphs, edge costs $\ge$ Manhattan length ⇒ monotone held.
* 🔎 Standard facts: monotone with $h(\text{goal})=0$ ⇒ admissible; the converse fails (an admissible $h$ need not be monotone).

### 4.2 Consequence 1 — $f$ never decreases along a path 🧪

With $n$ a successor of $m$: $h(m)-h(n)\le k(m,n)$. Add $g(m)$ to both sides and use $g(n)=g(m)+k(m,n)$:

$$g(m)+h(m)\;\le\;g(m)+k(m,n)+h(n)=g(n)+h(n)\quad\Longrightarrow\quad f(m)\le f(n)$$

(Along an optimal path $g$ may be replaced by $g^{\ast}$.) So $f$ values are **non-decreasing** as we approach the goal. ✅ 194/194 random instances: expanded nodes came out in non-decreasing $f$.

### 4.3 Consequence 2 — $g(n)=g^{\ast}(n)$ whenever A\* expands $n$ 🧪

*Proof by contradiction.* Suppose A\* is about to expand $n$ with $g(n)>g^{\ast}(n)$.

1. Let $n_L$ be the **last node on an optimal path to $n$ that has been expanded**; its successor $n_{L+1}$ on that path is on **OPEN** (it exists because $n$ itself was not reached optimally).
2. By monotonicity (consequence 1 along the optimal path, using $g^{\ast}$): $f(n_{L+1})=g^{\ast}(n_{L+1})+h(n_{L+1})\le g^{\ast}(n)+h(n)$.
3. A\* picks $n$ before $n_{L+1}$ ⇒ $f(n)\le f(n_{L+1})$, i.e. $g(n)+h(n)\le g^{\ast}(n)+h(n)$.
4. Cancel $h(n)$: $g(n)\le g^{\ast}(n)$; also $g^{\ast}(n)\le g(n)$ always ⇒ $\mathbf{g(n)=g^{\ast}(n)}$. ∎

### 4.4 Consequence 3 — simplified A\*

* A\* behaves like **Dijkstra**: when a node is added to CLOSED its cost is final.
* ⇒ **Case 3 (node on CLOSED with a better path) never occurs** ⇒ **no Propagate-Improvement** needed.
* ⇒ CLOSED matters less; we can **prune CLOSED** (§6), as long as the search does not *leak back* and the path can still be reconstructed.
* ✅ Code (194 monotone grid instances): **0 reopenings**, $g=g^{\ast}$ at every expansion.

## 5. Motivation: sequence alignment in biology

* **DNA/RNA sequence** = string over $\{A,C,G,T\}$ (adenine, cytosine, guanine, thymine). **Sequence alignment** = measure similarity of two sequences (also used to stitch fragments together; informs evolution studies).
* **Needleman–Wunsch (1970):** dynamic-programming algorithm; **blind**, closer to Branch & Bound, explores the **whole** space. Later work uses A\* variants.
* **Alignment = place the sequences side by side, optionally inserting gaps.** Two penalties: **mismatch** (aligning different characters) and **indel** (insertion/deletion of a gap). Minimise total penalty.

**Examples (✅ DP-verified):**

| Strings | Indel | Mismatch | Best alignment | Cost |
|---|---|---|---|---|
| CG vs CA | 3 | **7** | two gaps (3+3) beats the mismatch (7) | **6** |
| CG vs CA | 3 | **5** | align directly | **5** |
| longer pair (three aligned after one shift) | 3 | 2 | one gap + one mismatch (3+2) vs three mismatches (2+2+2) | **5** vs 6 |

⇒ the best alignment **depends on the penalties**.

**Similarity vs distance:** they are inverses. With a similarity score the problem is a *maximisation*: e.g. $+1$ match, $-1$ mismatch/indel; or match 0, indel $-1$, mismatch $-10$; or a fine-grained matrix (diagonal weights A highest, G 7, C 9, T 8; off-diagonal negative; T–C mismatch costs 0).

### 5.1 As graph search

Moves from a node (position $(i,j)$ in the two strings):

| Move | Meaning | Edge cost |
|---|---|---|
| diagonal | align $X_i$ with $Y_j$ | match/mismatch cost |
| horizontal | insert a gap in one string | indel |
| vertical | insert a gap in the other | indel |

* Directed grid (no moves left/up). Start = top-left, goal = bottom-right. Strings need not be equal length (goal shifts). For lengths $N,M$ the grid has $(N+1)(M+1)$ nodes.
* Lecture example: horizontal `GCATGCA`, vertical `GATTACA`.
* Extreme path: all horizontal then all vertical = no alignment at all.

### 5.2 Size of the problem 🧪

* **Distinct paths:** with only horizontal/vertical moves (Manhattan city): $\displaystyle\binom{N+M}{N}=\frac{(N+M)!}{N!\,M!}$. With diagonals:

$$\#\text{paths}=\sum_{r=0}^{\min(N,M)}\frac{(N+M-r)!}{(N-r)!\,(M-r)!\,r!}\qquad(r=\text{number of diagonal moves})$$

  ✅ $N=M=3$: 20 vs 63; $N=4,M=6$: 210 vs 1289 ⇒ combinatorial growth.
* **Nodes** grow **quadratically** with depth (city-map grid).
* **A\* memory:** **OPEN grows linearly** (at most about twice the grid width), **CLOSED grows with the area ⇒ quadratic.** ✅ Random sequences of length 20/40/80 under A\* with $h=\lvert\text{remaining length difference}\rvert\cdot$ indel: CLOSED 269/765/2782 (of 441/1681/6561 grid nodes) while OPEN stayed ≈ $2L$.
* Real sequences have hundreds of thousands of characters ⇒ quadratic CLOSED is formidable ⇒ **prune CLOSED**.
* **Roles of CLOSED:** (i) avoid infinite loops / revisits ("leaking back"); (ii) **reconstruct the path**. In practice implement CLOSED as a **hash table** (fastest access).

## 6. Pruning CLOSED: Frontier Search, DCFS, SMGS

Recap: for monotone $h$, A\* never revisits CLOSED nodes, so we need only stop the search from **leaking back** and still produce a path.

### 6.1 Frontier Search (Korf & Zhang, 2000)

* Store only **OPEN** nodes. Each OPEN node carries a list of **barred (tabu) nodes** — closed neighbours it must **not generate** again.
* When $A$ is expanded: for each neighbour that is new or on OPEN, add $A$ to its barred list; CLOSED nodes (shown grey) are **deleted**.
* Extra memory: only a **constant factor** (a few barred entries per OPEN node), not growing with depth.
* **Path reconstruction problem:** deleted nodes lose the ancestors. Solution: keep a **relay layer** of nodes where $g(n)\approx h(n)$ (roughly **half-way** to the goal); every later node records its relay ancestor.

### 6.2 Divide-and-Conquer Frontier Search (DCFS)

* On finding the goal, we know its **relay node** $r$. Recursively solve **start → $r$** and **$r$ → goal**; each sub-problem again has its own relay node (so 2, then 4, … segments).
* **Time:** if A\* needs $T(d)$ (exponential), the recursion costs about

$$T_{\text{DCFS}}(d)\;\approx\;T(d)\cdot d\qquad(\text{solution of the recurrence})$$

  — **extra time factor $d$** in exchange for **much less space** (only one relay layer + frontier), so larger problems fit.

### 6.3 SMGS (Zhou & Hansen, 2003)

* Idea: memory is cheap — **don't divide** unless needed. If the problem fits, just run A\*; **create a relay layer only when memory is nearly exhausted** (may create **several** relay layers, or none). Hence *"smart"*. (⚠️ The lecture calls it **Smart Memory Graph Search**; the algorithm sheet writes **Sparse-Memory Graph Search** — same SMGS.)
* **Classification of CLOSED nodes** ($I$ = interior nodes = those whose lowest-cost path is known):

| Node class | Lecture wording | Sheet formula 📎 |
|---|---|---|
| **BOUNDARY** (yellow) | a closed node with **at least one child on OPEN** | $\text{BOUNDARY}(I)=\{b\in I\mid\exists p\,(p\in\text{Pred}(b)\wedge p\notin I)\}$ $=I\setminus\text{KERNEL}(I)$ |
| **KERNEL** (grey) | a closed node whose **neighbours are all closed** | $\text{KERNEL}(I)=\{k\in I\mid\forall p\,(p\in\text{Pred}(k)\Rightarrow p\in I)\}$ |

* The **boundary** prevents leaking back; **kernel** nodes can be **deleted** when memory is needed. SMGS converts the boundary into a **relay layer** and deletes the kernel, then continues.
* At termination: a **sparse** path (start → relay$_1$ → relay$_2$ …) plus the **dense** path (the unpruned stretch from the last relay to the goal); the sparse path is turned into a dense one by that many **recursive calls**.
* Memory structure ("open, boundary, kernel"): **OPEN unchanged**; CLOSED split into boundary (unrestricted memory) and kernel (fixed-size, periodically cleared) 📎.
* Korf & Zhang always split in halves; Zhou & Hansen split **only when needed**.

## 7. Pruning OPEN: beam-based algorithms

OPEN usually grows faster than CLOSED in exponential trees (4 children ⇒ 4, 16, 64, …; DFID's extra work is only $\tfrac{b}{b-1}$).

### 7.1 Beam search with $f$-values

* Keep only the **$w$ best nodes per level** (width $w$ = beam width; larger today because memory is cheap).
* ⚠️ **Different from the hill-climbing beam** of Weeks 3–4: here we search for a **path** and rank by **$f=g+h$**; since $f$ values **increase** with depth we can't use "continue only if better" — always keep the $w$ best. Terminate when the **goal is reached** (hopefully even in infinite graphs).
* **Space $=w\cdot d$** ⇒ linear in depth; **not admissible**.

### 7.2 Upper bound $U$ and pruning 🧪

* A beam run gives a path of cost $U$ ⇒ **$U$ is an upper bound** on the optimal cost; $h(S)$ is the lower bound.
* **Prune every node with $f(n)>U$** — since $f$ never decreases along a path (monotone), any path through it costs more than $U$.
* A\* automatically stays within it: every expanded node has $f(n)\le f^{\ast}\le U$.
* ✅ 184 random monotone instances: beam ($w=2$) gave $U\ge$ optimum in all, and A\* pruned at $f>U$ still returned the optimum.

### 7.3 The Zhou–Hansen family

| Algorithm | Idea | Space | Admissible? |
|---|---|---|---|
| **BFHS** — Breadth-First Heuristic Search (2004) | blind **BFS**, but only expand nodes with $f\le U$ ("heuristic" because of the bound) | frontier inside the $U$-contour; empirically **smaller than A\***'s | **Yes** |
| **D&C BFHS** | BFHS with SMGS-style **open + boundary + relay layers** | reduced | Yes |
| **D&C Beam Search** | beam search keeping only **3 layers** (open, boundary, relay) of width $w$ | $3w=O(1)$ | **No** |
| **Beam Stack Search** | **beam search + backtracking**; a **beam stack** stores per level $(f_{\min},f_{\max})$ | beam $\times$ depth + stack | **Yes** (sweeps the $U$-bounded space) |
| **D&C Beam Stack Search** | like D&C beam search but **backtracks by regenerating from the start**, guided by the beam stack | **$O(1)$** (ignoring the depth-$d$ beam stack of two numbers per level) | Yes |

**Beam stack** (🧪 conceptually): at each level it stores
* $f_{\min}$ = the lowest $f$ among nodes in the beam (closed end of the interval),
* $f_{\max}$ = the lowest $f$ of nodes **just outside** the beam (open end),

i.e. a half-open window $[f_{\min},f_{\max})$. When backtracking, it **slides** the window to the next set of nodes at that level, so over time the beam **sweeps from low to high $f$ across the whole space inside the bound $U$**. In the D&C version parents are deleted, so a node is **regenerated from the start**, guided by the stack at every level.

Space ladder: A\* exponential → prune CLOSED (frontier/SMGS) → prune OPEN (beam stack) → D&C beam stack: constant.

## 8. Linear-space versions: IDA-star and RBFS

Both are due to **Richard Korf** and give **admissible** search in **linear space**, at the cost of **repeated work**. 🔎 Pseudocode below is a standard reconstruction of what the lecture describes.

### 8.1 IDA\* (Iterative Deepening A\*)

* Series of **depth-first searches** (linear space), like **DFID**, but the cutoff is an **$f$-bound** instead of depth.
* Initial bound $=f(S)=h(S)$ — no solution can cost less than $h(S)$ because $h(S)\le h^{\ast}(S)$.
* After a failed iteration the bound is raised to the **smallest $f$ value that exceeded the old bound** ("the $f$ of the cheapest unexpanded node") — **not** $+1$ as in DFID.
* Returns the **optimal** path (for admissible $h$); **explores the same nodes as A\*** but via repeated searches.

```text
IDA*(S)
  bound ← h(S)
  repeat
      (t, solution) ← DFS-f(S, g=0, bound)       # DFS that cuts off any node with f = g+h > bound
      if solution found: return it
      if t = ∞: return failure
      bound ← t                                   # t = min f among nodes cut off in this round
```

**Drawbacks 🧪:**
* **No sense of direction** (DFS), lots of **repeated work**, especially when all nodes have **different $f$ values**: each round extends the bound by just one new node ⇒ the number of rounds explodes; and it doesn't keep CLOSED (as in DFID).
* **Fix:** raise the bound by a **constant $\delta$** each round instead of to the next $f$ — fewer rounds, but a **loss of optimality** (the DFS may find a path inside the wider contour that is not the cheapest); $\delta$ controls the loss.

### 8.2 RBFS (Recursive Best-First Search, Korf 1991)

* **Linear space** and **sense of direction** (best-first); "like **hill climbing with backtracking**".
* Keeps only the current path and, for every node on it, its **best alternative ("second best")** value.
* Descends to the **best successor** (need not be better than the current node — $f$ increases with depth). It keeps going **as long as the best successor's $f\le$ second-best**.
* When all children exceed the second-best, it **rolls back**: it **deletes** the explored subtree but **backs up the minimum $f$ of the children into the parent** ("a better estimate"), then restarts from the second-best node.

**Lecture example (backed-up values):**
Start at $f=50$ → 59 (best child) → 55 … The best path goes 55 → 56 → 56 → 57 → 58, with **59 remembered as the second best**. At the node with $f=58$ the three children have $61,62,63$, all $>59$ ⇒ roll back: its value becomes $\min=61$; its parent (57) becomes $\min(61,\,60,\,64\ldots)=60$; the next parent (56) becomes 60; … the root-side node that was 55 becomes **60**; search restarts in a **new direction** (the 59 branch).

```text
RBFS(n, f_n, f_limit)                    # returns (solution, backed-up f of n)
    if goal(n): return (solution, f_n)
    succ ← children of n with f(c) = max( g(c)+h(c), f_n )        # backed-up values never below parent's
    loop:
        best ← child with lowest f;   alt ← second-lowest f among children
        if best.f > f_limit: return (failure, best.f)             # roll back with updated estimate
        (sol, best.f) ← RBFS(best, best.f, min(f_limit, alt))
        if sol: return sol
```

* **Problem — thrashing:** if paths look similar, RBFS repeatedly rolls back and forth (e.g. 59 rises to 62/63 and it flips again); **re-expands** many nodes.
* In the demo $k$ in RBFS is the **WA\* weight** (set to 1 to compare with A\*).
* Exercise in the lecture (500 → 550 → 570 → 590): perform two more expansions and the roll-back; not solvable from the transcript alone.

### 8.3 DFID vs IDA\* vs RBFS

| | **DFID** | **IDA\*** | **RBFS** |
|---|---|---|---|
| Cutoff / guide | depth | **$f$-bound** (next unexpanded $f$) | $f$ of **second-best** alternative |
| Space | linear | **linear** | **linear** |
| Direction | none | none (DFS) | **yes** (best-first) |
| Repeated work | small factor $\tfrac{b}{b-1}$ | can be **large** (many distinct $f$) | can **thrash** |
| Optimal | shortest in hops | **optimal** (admissible $h$) | optimal (admissible $h$) |

(Student implementations in the AIDB lab; black = CLOSED, blue = OPEN.)

* **Best-First** heads straight to the goal; **A\*** explores more, looking left and right, because it also minimises $g$.

## 12. Quiz-preparation tips

### Mechanics

1. **WA\* trace:** compute $f=g+w\cdot h$ for **every** generated node; with $w=2$ double all $h$ values first. Only the *ranking* formula changes — the update rule (`g(M) > g(N)+k(N,M)`), parent pointers and the three cases are the same as in A\*.
2. **Monotone check:** test **every edge in both directions**: $h(m)-h(n)\le k(m,n)$ and $h(n)-h(m)\le k(m,n)$ (for undirected edges). One violation ⇒ not monotone.
3. When asked "which node does A\* expand next?", take the **lowest $f$**; under a **monotone** heuristic the $f$ values of expanded nodes form a **non-decreasing** sequence — a good sanity check on a worked answer.
4. **IDA\*:** new bound = the **smallest $f$ among nodes cut off** in the last round (not $+1$). Count rounds: with all-distinct $f$'s expect one new node per round.
5. **RBFS:** after a rollback, a parent's value = the **minimum** of its children's backed-up values; the next node explored is the one with the best backed-up value overall (second-best on the path).
6. **Beam:** keep exactly $w$ best by $f$ at each level (ties → alphabetical label, course rule); beam search is **not** admissible; the cost it returns is an **upper bound $U$**.
7. **Alignment:** a diagonal move costs the match/mismatch penalty, horizontal/vertical costs the **indel**; compute both alternatives (e.g. two gaps vs one mismatch).

### Concepts

* **WA\*:** more weight ⇒ fewer nodes ⇒ possibly non-optimal; $w=1$ is A\*, $w=0$ is B&B.
* **Monotone ⇒** Dijkstra-like behaviour: no reopening, $f$ non-decreasing, $g=g^{\ast}$ at expansion.
* **Space bottlenecks:** exponential trees → OPEN dominates; grid-like problems (alignment, route finding) → **CLOSED quadratic, OPEN linear**.
* **Two roles of CLOSED:** avoid leaking back; reconstruct the path — frontier search solves the first with **barred lists**, the second with **relay nodes**.
* **DCFS** pays a factor $d$ in time; **SMGS** pays it only when memory runs out.
* **Upper bound pruning:** any heuristic path cost $U$ lets you cut nodes with $f>U$.
* **Beam variants:** inadmissible (beam, D&C beam) vs admissible (BFHS, beam stack, D&C beam stack).
* **IDA\* vs DFID:** same iterative deepening, different bound ($f$ vs depth). **RBFS** has direction, IDA\* doesn't.

### Frequent traps ⚠️

* Claiming WA\* with $w>1$ is admissible (it's not guaranteed).
* Forgetting that **Case 3 can still occur in WA\*/non-monotone A\***; it can't for monotone $h$.
* Mixing up **monotone** with **admissible** — monotone is stronger.
* Writing the monotone inequality with the wrong direction: it is $h(\text{parent})-h(\text{child})\le k$.
* Saying "KERNEL nodes are on OPEN" — kernel nodes are **closed** with all neighbours closed; BOUNDARY nodes are closed with **at least one OPEN child**.
* Calling SMGS "Smart Memory" vs "Sparse Memory": the same algorithm — know both names.
* Believing IDA\* uses $+1$ increments (that's DFID).
* Saying RBFS stores the whole tree — it stores only the current path and the alternatives.
* Treating beam-search space as constant: it is $w\cdot d$ (only the **D&C** variant is $O(1)$).

# PART A — WEEK 7: GAME PLAYING

## A1. Summary of Part A

* **Shift of setting:** all earlier weeks had **one agent** solving a problem. Games have **several agents** whose outcomes depend on each other. **Game theory** models rational, self-interested agents; its key concepts are **payoff**, **strategy** and **Nash equilibrium**.
* **Classification of games** along three axes: payoff (**zero-sum / positive-sum / negative-sum**), number of players, and uncertainty (**incomplete information** or **stochastic** moves). Our target: **board games** (chess, Go, tic-tac-toe) = two-player, zero-sum, complete information, alternating, deterministic.
* **Game tree:** layers of **MAX** (square) and **MIN** (circle) nodes; leaf outcomes seen from MAX's view ($W=+1$, $D=0$, $L=-1$). **Minimax rule:** MAX backs up the largest child value, MIN the smallest. The minimax value is the game's analogue of the **Nash equilibrium**.
* **Strategy** (for MAX) = subtree with **one** child at every MAX node and **all** children at every MIN node. Value of a strategy = **minimum** of its leaves. The best move = root of the best strategy.
* Real trees are huge (chess $\approx10^{120}$ leaves) ⇒ **$k$-ply look-ahead** + **evaluation function** (material + positional) at the horizon, repeated after every move. Evaluation is never perfect ⇒ **horizon effect**.
* **Algorithms:** *minimax* (whole depth-first sweep), *alpha-beta* (depth-first, left-to-right, prunes; amount of pruning depends on node order), **SSS\*** (best-first: refine the *best cluster* of strategies; upper bounds; very little search, sense of direction).
* All three return the **same minimax value**; pruning order: minimax (none) < alpha-beta < SSS\* (usually).

## A2. Game theory and types of games

### A2.1 Definitions 🧪

* **Game theory** = a framework for social situations among competing (or cooperating) players; the **science of strategy / optimal decision making of independent actors**. Pioneers: **John von Neumann, Oskar Morgenstern, John Nash**.
* A game specifies the **players**, their **preferences** (payoffs), their **available strategies**, and how strategies determine the **outcome**. A player's payoff depends on **other players' strategies** too.
* **Rational agent** (assumed): perfect reasoner, acts only in **self-interest**, maximises own payoff.
* **Nash equilibrium:** an outcome from which **no player can improve by changing decision unilaterally** ("no regrets"). Most games have one (not all).
* **Payoff** is more general than reward/penalty (can be negative, e.g. years in prison).
* Rational self-interest can give a result **worse for everybody** than cooperation, and the outcome may be **intended by none** of the agents.

### A2.2 Prisoner's dilemma 🧪

Two arrested gang members are interrogated separately; each may **cooperate** (stay silent) or **defect/betray**. Payoffs $(A,B)$ = minus years in prison:

| | **B cooperates** | **B defects** |
|---|---|---|
| **A cooperates** | $(-1,\,-1)$ **R** (reward) | $(-3,\,0)$ **S** (sucker) for A, **T** (temptation) for B |
| **A defects** | $(0,\,-3)$ **T** for A, **S** for B | $(-2,\,-2)$ **P** (punishment) |

* Standard letters: $T=0$, $R=-1$, $P=-2$, $S=-3$. If
$$T>R>P>S$$
  both players end up **defecting**, even if the game is repeated.
* **Reasoning:** if B defects, A gets $-2$ (defect) vs $-3$ (cooperate) ⇒ defect; if B cooperates, A gets $0$ vs $-1$ ⇒ defect. Defection is the **best reply to everything** (dominant strategy) ⇒ **Nash equilibrium $(D,D)=(-2,-2)$**.
* Mutual cooperation $(-1,-1)$ is **Pareto optimal** (total 2 years vs 4 years for $(D,D)$), yet not an equilibrium.
* It is a **single-move** game. Real games (chess) need **many moves** ⇒ game trees.
* Real-life illustrations used: price wars (negative-sum), opposition parties failing to cooperate, geopolitical stand-offs.

### A2.3 Types of games 🧪

| Axis | Type | Meaning / example |
|---|---|---|
| **Payoff** | **Zero-sum** | total payoff 0; what one wins the other loses (chess) |
| | **Positive-sum** | cooperation; most players gain (students studying together) |
| | **Negative-sum** | competition; most/all lose (price war between two airlines) |
| **Players** | 2-player | chess, price war between 2 firms |
| | multi-player / **team games** | 2 teams of 2 (contract bridge); football; at team level it is again a 2-player game; adding the consumer turns a price war into zero-sum |
| **Uncertainty** | **Incomplete information** | cannot see opponents' cards or plans (bridge, poker, war, business: espionage, deception, e.g. *Operation Fortitude*) |
| | **Stochastic** | dice or chance in actions (backgammon, snakes & ladders, poker draws, basketball throws) |

## A4. Board games, game trees, minimax and strategies

### A4.1 What is a board game? 🧪

Two-player · **zero-sum** (win $+1$, loss $-1$, draw $0$) · **complete information** (both see the board) · **alternate moves** (a double move can be modelled as a compound move) · **deterministic** (no chance). Examples: chess, Go, tic-tac-toe (noughts and crosses).

### A4.2 Game tree

* **Layered tree**: **MAX** (square) moves at the root, then **MIN** (circle), alternately. Every root-to-leaf path is a complete game.
* Leaf labels are from **MAX's point of view**: $W$ ($+1$), $D$ ($0$), $L$ ($-1$). The tree defines the **rules** of the game.
* We write the program for MAX, who moves first.

### A4.3 Minimax backup rule 🧪

$$\text{val}(J)=\begin{cases}\text{outcome}(J) & J\text{ is a leaf}\\ \max_{c\in\text{children}(J)}\text{val}(c) & J\text{ is a MAX node}\\ \min_{c\in\text{children}(J)}\text{val}(c) & J\text{ is a MIN node}\end{cases}$$

* If both players play perfectly, the **minimax value** is the outcome — the game's **Nash equilibrium**. (Tic-tac-toe: always a draw.)
* Values can be backed up **bottom-up in any order** (breadth-first or depth-first) as long as the children have values.
* Lecture's worked tree: MAX at the root can choose among values $0$, $+1$, $-1$ ⇒ minimax value $+1$ (a forced win for MAX).

### A4.4 Strategies 🧪

* **Strategy for MAX:** a subtree built from the root: at a **MAX** level choose **one** child (freeze MAX's choice); at a **MIN** level choose **all** children (MIN's choice unknown).
* The **value of a strategy** is decided by MIN: $\;\text{val}(\text{strategy})=\min$ of the leaves in the strategy.
* A strategy all of whose leaves are $W$ is a **winning strategy**. In the lecture's example one MAX strategy is winning (leaves all $W$), another lets MIN force a draw.
* The game actually played = **intersection** of MAX's strategy and MIN's strategy (a single path).
* Choosing a move = choosing a strategy (like the prisoner's dilemma, but with look-ahead built in).
* **Counting MAX strategies** in a uniform tree with branching $b$ and $d$ plies (my recurrence; ✅):

$$N_{\max}(0)=1,\qquad N_{\max}(k)=b\cdot N_{\min}(k-1),\qquad N_{\min}(k)=\bigl(N_{\max}(k-1)\bigr)^{b}$$

  Binary tree, 4 plies (16 leaves): **8 strategies** ✅ (lecture); $b=3,d=4$: 81.
* **Complexity table**

| Game | Moves / branching | Tree size |
|---|---|---|
| Tic-tac-toe | 9, 8, 7, … (3 distinct first moves with symmetry) | $9!=362\,880$ games |
| Chess | 20 first moves (16 pawn + 4 knight); average branching factor **35**; about 40 moves per player ⇒ depth 80 | $\approx35^{80}\approx10^{120}$ leaves (lecture's estimate; $35^{80}=10^{123.5}$ ✅) |
| Go | $19\times19$ board | much larger |

  At $10^{12}$ leaves per second, $10^{120}$ leaves need $10^{108}$ seconds; even with $10^{75}$ particles each inspecting $10^{12}$ leaves/s it needs about $10^{22}$ centuries ⇒ **full analysis is impossible**. Deep Blue beating Kasparov only means it played *better*, not perfectly.

### A4.5 $k$-ply look-ahead 🧪

1. Choose $k$ (a **ply** = one move by one player).
2. Search the tree to depth $k$; at each **horizon** (leaf of the $k$-ply tree) apply the **evaluation function**.
3. Back up values with the minimax rule; **make the best move**.
4. Wait for the opponent's move (that time can be used for extra computation), then **repeat the $k$-ply search from the new position**.

We search repeatedly because evaluation functions are imperfect, like heuristics earlier in the course.

## A5. The evaluation function and look-ahead

### A5.1 Definition

A **static function** $e(\text{board})$ returning a value in $[-\text{large},+\text{large}]$, normally scaled to $[-1,+1]$. It replaces the three labels $\{-1,0,+1\}$ by a continuum: **positive = good for MAX, negative = good for MIN**; $\pm1$ still mean a won game.

Typical components: **material strength** (pieces on both sides) and **positional strength** (mobility, board control, structure).

### A5.2 Tic-tac-toe evaluation (2-ply example) 🧪

$$e(n)=\#\{\text{rows, columns, diagonals still open to MAX}\}-\#\{\text{open to MIN}\}$$

A line is **open to a player** if it contains no opponent mark. Position: X (MAX) in a corner, O (MIN) in the centre ⇒ MAX has **4** open lines (its own row and column, plus the bottom row and right column — every line through the centre contains O), MIN has **5** (middle row, middle column, bottom row, right column, and the diagonal not through X's corner) ⇒ $e=4-5=-1$ ✅. Over the 5 distinct MIN replies (symmetric ones skipped) the values are $1,0,1,0,-1$; MIN backs up the smallest, $-1$. (True game value is 0 — the evaluation is only an estimate.)

### A5.3 Shannon's chess evaluation 🧪🔎

Count the difference (mine − opponent's) of each piece type, weight it, add positional penalties:

| Piece | King | Queen | Rook | Bishop | Knight | Pawn |
|---|---|---|---|---|---|---|
| Weight | **200** | **9** | **5** | **3** | **3** | **1** |

$$e=200(K-K')+9(Q-Q')+5(R-R')+3(B-B'+N-N')+(P-P')\;-\;c_1(D-D'+S-S'+I-I')\;+\;c_2(M-M')$$

* $D$ = doubled pawns, $S$ = blocked pieces, $I$ = isolated pawns, $M$ = mobility (number of legal moves). (The lecture describes these verbally; Shannon's constants are $c_1=0.5$, $c_2=0.1$ 🔎.)
* Example from the lecture: 2 rooks vs 0 ⇒ $+2\cdot5=+10$; losing a queen ⇒ $-9$. Weight 200 for the king is harmless: both kings stay on board.
* **Positional features** (chess lore): mobility, **control of the centre**, development, **king safety** (castling; in the endgame the king becomes active), **pawn structure** (chained pawns good; isolated/doubled/head-to-head bad; pawns about to promote valuable), **double rooks** (rooks on the same column), **pair of bishops** > bishop + knight, knights in certain endgames, **forks, pins, discovered attacks**.
* **Deep Blue's** evaluation had about **8000 components**.
* **Where does $e$ come from?** Human experts originally; now **learned** by (deep) **reinforcement learning** — Samuel's checkers, TD-Gammon, AlphaGo (from expert games), **AlphaGo Zero** (from rules only, self-play).

### A5.4 Look-ahead vs evaluation 🧪

* If $e$ were perfect, 1-ply search would suffice. Grandmasters store tens of thousands of schemata (de Groot) and recognise good positions without look-ahead, but writing such an $e$ is hard.
* Hence the combination: search to depth $k$ and evaluate at the horizon. **Patrick Winston:** with about **15-ply** search even a reasonable evaluation function plays at grandmaster level.
* A pattern such as a **fork** (a knight attacking two pieces) can be put in $e$ so that it is detected without extra look-ahead.
* **Zugzwang:** a position where *having to move* is a disadvantage (any move worsens the position) — so a good $e$ should depend on **who is to move**.
* **Poisoned rook** (a contrived fortress position given to *Deep Thought*, 10–11 ply): the program captured the offered rook and wrecked its own wall; a human sees the position cannot be broken (draw). **Finite look-ahead and imperfect evaluation can mislead.**

## A6. Minimax and alpha-beta (recap)

(From the SSS\* lectures' recap; 🔎 marks standard material.)

* **Minimax:** search the $k$-ply tree **depth-first**, evaluate the leaves, back up max/min. **No pruning** — it inspects every leaf ($b^k$ leaves).
* **Alpha-beta (McCarthy):** also **depth-first, left to right**, but prunes branches that cannot affect the result.
  * $\alpha$ = best (largest) value MAX is already guaranteed on the path, $\beta$ = best (smallest) value MIN is guaranteed; **cut off when $\alpha\ge\beta$** 🔎.
  * A MAX node that has seen a child with value $v$ knows its value is $\ge v$ (this is the *alpha* bound); the lecture shows that SSS\* produces the same "alpha cut-offs".
  * **The amount of pruning depends on node ordering:** best moves first ⇒ much pruning; otherwise little. (🔎 best case about $b^{k/2}$ leaves.)
  * It is **blind**: always left-to-right, no sense of direction.
* Both return the **same minimax value** as plain minimax (✅ 300/300 random trees).

```text
alphabeta(node, α, β)                                  🔎
   if leaf: return e(node)
   if node is MAX:  v ← −∞;  for each child c:  v ← max(v, alphabeta(c, α, β));  α ← max(α, v);  if α ≥ β: break;  return v
   else (MIN):      v ← +∞;  for each child c:  v ← min(v, alphabeta(c, α, β));  β ← min(β, v);  if α ≥ β: break;  return v
```

## A7. SSS-star: best-first game-tree search

**SSS\*** (Stockman, **1979**) is the **best-first** version of game-tree search: instead of sweeping left-to-right it has a **sense of direction**. It applies the course's general principle:

> *Find the best-looking partial solution and refine it until the best solution is fully refined.*

Here a **solution = a strategy**, a **partial solution = a cluster of strategies**, and the estimate is an **upper bound** (like the lower bounds used in TSP branch & bound, but for a maximisation).

### A7.1 Clusters 🧪

* Any **leaf** (horizon node) with value $v$ represents a **cluster of partial strategies**; every strategy in the cluster has value $\le v$ (MIN can only drive it lower once more leaves are seen). Lecture example: leaf 15 belongs to two strategies (LRL, LRR) ⇒ both $\le15$.
* **Initial clusters** (cover *all* strategies, so the best one cannot be missed): from the root go down and
  * at a **MAX** level take **all** children,
  * at a **MIN** level take **one** child (WLOG the leftmost),

  until the horizon. ⚠️ This is the **opposite** of a strategy (a strategy takes *one* at MAX and *all* at MIN) — don't confuse them.
* Small example: binary tree with 16 leaves has 8 strategies; initial clusters are the four leaves **21, 15, 5, 13**, each covering 2 strategies.

### A7.2 The algorithm 🧪

Maintain a **priority queue OPEN** of triples $(N,\ \text{status},\ h)$, status $\in\{\textit{live},\textit{solved}\}$; $h$ = upper bound (value if solved). The node with the **highest $h$** is popped first. Start with $(\text{root},\textit{live},+\infty)$; **terminate when the root is solved and at the head of OPEN** — the answer is its $h$.

```text
SSS*(root)
 OPEN ← { (root, live, +∞) }
 loop:
   (N, status, h) ← pop the entry with highest h
   if N = root and status = solved:  return h                               # terminate
   if status = live:                                                        # FORWARD phase: build clusters
        if N is a terminal (horizon) node:   push (N, solved, min(h, eval(N)))
        else if N is MAX:   for each child C of N:  push (C, live, h)       # all children
        else (N is MIN):    push (first child of N, live, h)                # one child
   else (status = solved):                                                  # BACKWARD phase: refine / back up
        P ← parent(N)
        if N is MAX:
             if N is not the last child of P:  push (next sibling of N, live, h)     # "recursive call", bound h
             else:                             push (P, solved, h)                    # all siblings done ⇒ parent solved
        else (N is MIN):
             push (P, solved, h);   remove all successors of P from OPEN              # alpha cut-off
```

Notes 🧪:

* A MIN node popped as *solved* is the best node in OPEN, so its siblings (all $\le h$) cannot help ⇒ the MAX parent is solved with value $h$ and **the other children are discarded**.
* The bound $h$ handed to a newly added sibling is the value just found; a leaf evaluated later gets $\min(h,\,eval)$ — so a leaf worth 40 under bound 32 is **stored as 32** and doesn't influence the parent.
* For implementation add a 4th field **player (MAX/MIN)** to each triple.
* **Three phases in the lecture's words:** initial (add the root), **forward** (go down to the horizon building clusters, evaluate leaves), **backward** (apply the minimax backup and refine).

### A7.3 Worked example 1 (the 16-leaf tree) ✅

Initial clusters (upper bounds) A=21, B=15, C=5, D=13; MIN parent on top of each.

1. Best = **21**: refine (look at its sibling, value 5) ⇒ its MIN parent solves to **5**.
2. New best = **15** ⇒ sibling 11 ⇒ MIN parent **11**; the competing cluster with value 5 is **cut off** (MAX will take 11).
3. New best = **13** ⇒ sibling 12 ⇒ **12**; the other cluster with value 5 is cut off.
4. Two contenders: **11** and **12** (MAX nodes, solved) — MAX's choice is not final because MIN sits above them.
5. Best solved MAX node (12) is **not the last child** ⇒ add its sibling subtree as live with bound **12** (a "recursive call"). Its clusters 13 and 7: refine 13 (value $\ge13$, *alpha* value) ⇒ the 7 cluster is cut off; since 13 > 12 the MIN parent keeps **12** ⇒ solved.
6. Root's other branch has bound $\le 11 < 12$ ⇒ discarded ⇒ **root solved = 12**.

The final strategy has leaves **13, 12, 13, 14**; minimax value **12**.

### A7.4 Worked example 2 (larger tree, lecture) 🧪

* Six initial live clusters; evaluated left to right, then the best cluster **60**: look at its sibling 57 ⇒ MIN parent 57; MAX grandparent now $\ge57$; the cluster with value 55 (≤55) is **cut off**.
* Refine 57's MAX node: add the next child as live with bound 57; new leaves 17 and 15 (< 57) go to the back of the queue.
* Continue with the best remaining clusters (50→12, 45→35, 40→30, 35, 32 …); alpha cut-offs repeat; each time a solved MAX node has more siblings, those are added with the new bound (57, 35, 32).
* Final: a leaf 38 under bound 32 is stored as 32; the root solves to **32**.
* **Alpha-beta looked at nodes (e.g. 40, 60) that SSS\* never touched** — SSS\* prunes more because it keeps working on the most promising subtree. Replace the 15 by a very good value and SSS\* would stay in that subtree: it is **best-first**.
* Exercise left by the lecturer: put any values in the pruned (grey) leaves — the minimax value stays 32.

### A7.5 Properties ✅

| | |
|---|---|
| Returns | the **same minimax value** as minimax and alpha-beta |
| Search order | **best-first** (sense of direction) vs alpha-beta's blind left-to-right |
| Pruning | typically the **most**: minimax < alpha-beta < SSS\* in nodes pruned |
| Cost | needs a priority queue (more memory than depth-first alpha-beta) 🔎 |
| Experiment (✅ 300 random trees, depth 4) | average leaves examined: minimax 48.1, alpha-beta 27.6, **SSS\* 21.6**; SSS\* examined more than alpha-beta in 25 trees (ties/ordering), so "usually, not always" |

## A8. Comparison, demo and horizon effect

### A8.1 Demo (lecture)

* **Minimax** sweeps the entire tree (brute force). **Alpha-beta** finds the same path but prunes. **SSS\*** first builds the clusters, then explores less than both.
* On a denser tree all three found value **59** from the same leaf; SSS\* explored the smallest part of the tree.
* **Practical meaning:** the more you prune, the **deeper** you can look in the same time: SSS\* > alpha-beta > minimax.

### A8.2 Horizon effect 🧪

A $k$-ply search cannot see beyond depth $k$. A bad event (e.g. MIN capturing MAX's queen) can be **pushed beyond the horizon** by delaying moves (two inconsequential knight moves), so MAX still picks that branch, unaware of the danger.
Simplest remedy (lecture): before committing to a move do a **secondary search** and check the minimax value does not fluctuate too much (e.g. from 50 to −12).

### A8.3 Comparison table

| | **Minimax** | **Alpha-beta** | **SSS\*** |
|---|---|---|---|
| Order | depth-first | depth-first, left→right | **best-first** (priority queue) |
| Pruning | none | yes, order-dependent | most |
| Sense of direction | none | none | **yes** |
| Estimate used | – | $\alpha,\beta$ bounds | **upper bounds** on clusters |
| Value returned | minimax | minimax | minimax |
| Memory | $O(bd)$ | $O(bd)$ | larger (OPEN) |

### A8.5 Quiz tips for Part A

1. **Evaluate from MAX's viewpoint** everywhere; positive is good for MAX.
2. **Minimax:** at a MIN level choose the *smaller* child value, at MAX the *larger*; check which level the root is.
3. **Strategy vs cluster:** strategy = 1 child at MAX, *all* at MIN; SSS\* initial cluster = *all* at MAX, 1 at MIN.
4. **SSS\*:** pop the **highest** $h$; the root must be **solved** *and* at the head to stop; solved MIN node ⇒ parent solved with the **same value** and siblings removed; solved MAX node not last ⇒ add next sibling **live** with bound = current value.
5. Leaf values are capped by the bound: $\min(h,\,eval)$.
6. All three algorithms give the **same value**; compare them by **leaves examined** — pruning order minimax < alpha-beta < SSS\* (usually).
7. Alpha-beta's pruning depends on **move ordering**; SSS\* does not rely on left-to-right order.
8. ⚠️ Don't confuse **look-ahead depth $k$** with **tree depth**, and **evaluation (horizon)** with **terminal outcome**.
9. Know the vocabulary: ply, horizon, material/positional, zugzwang, fork, horizon effect, Nash equilibrium = minimax value, zero-sum.

# PART B — WEEK 8: AUTOMATED PLANNING

## B1. Summary of Part B

* **Planning problem:** start in a given situation, reach a goal, and return the **path (plan = sequence of actions)** — unlike configuration problems, where only the final node matters. The planning community built **domain-independent** machinery: planners that work for many domains, given a *description language* (PDDL).
* **Action-centric view:** states are described by **predicates**; **operators/actions** have **preconditions** and **effects** (positive = *add list*, negative = *delete list*). Plans are **sequences of actions**, not sequences of states.
* **STRIPS domain** (simplest): finite, static, completely observable, one agent, hard goals on the final state, instantaneous deterministic actions. State transition system $\Sigma=(S,A,\gamma)$.
* **Blocks world:** predicates `on(X,Y)`, `ontable(X)`, `clear(X)`, `holding(X)`, `armempty`; operators **pickup, putdown, stack, unstack**.
* **Applicability and progression:** $a$ applicable in $s$ iff $\text{pre}(a)\subseteq s$; $\;s'=(s\setminus\text{eff}^-(a))\cup\text{eff}^+(a)$. A plan is valid iff $G\subseteq\gamma(s_0,\pi)$.
* **Relevance and regression:** $a$ relevant to $G$ iff $\text{eff}^+\cap G\neq\emptyset$ and $\text{eff}^-\cap G=\emptyset$; $\;G'=(G\setminus\text{eff}^+(a))\cup\text{pre}(a)$.
* **Forward state-space planning (FSSP):** sound (always legal states) but **high branching factor**. **Backward (BSSP):** low branching factor but **unsound**: regression can produce **inconsistent sub-goals** (holding A and holding B) ⇒ must **verify by progression**.
* **Goal Stack Planning (GSP):** backward *search* but forward *plan construction* (stack of goals, actions, preconditions) — a **linear planner**: solves goals one at a time; **goal order matters**; fails to be optimal on **non-serialisable sub-goals** (**Sussman's anomaly**).
* **Plan-space / partial-order planning (POP):** search the space of **partial plans** $\langle A,O,L,B\rangle$ (actions, ordering links, causal links, binding constraints); fix **flaws** — **open goals** (add a causal link from an existing action or a new action) and **threats** (resolve by **separation, promotion, demotion**). A plan with no flaws is a solution.

## B2. Domain-independent planning and STRIPS

### B2.1 Planning vs configuration; the action view 🧪

* **Configuration problem:** find a node satisfying criteria (SAT, N-Queens). **Planning problem:** find the **path / sequence of actions** from start to goal.
* Until now, **state-centred** (the solution is a sequence of states, `MoveGen` supplied). Planning is **action-centric**: *name* the actions, state when an action is **applicable** to a state and when it is **relevant** to a goal ⇒ **goal-directed** reasoning becomes possible.
* **State-space planning** searches states (plan is a by-product); **plan-space planning** searches directly among plans and represents **no states** at all.
* Planning = the **reasoning (deliberation)** part of the agent's **sense → deliberate → act** cycle (Ghallab, Nau, Traverso: *Automated Planning: Theory and Practice*).

### B2.2 Dimensions of planning domains 🧪

| Dimension | Simplest | More general |
|---|---|---|
| **Perception** | complete information (as in board games) | partial information |
| **Goals** | **satisfaction goals** on the final state (hard constraints) | **soft constraints** (penalty if unmet); **trajectory constraints** (constraints on the *path*, e.g. never more than 50 km from a petrol pump; "close the fridge after opening it"); soft trajectory constraints |
| **Action effects** | **deterministic** | **stochastic** (MDP planners; slipping on ice) |
| **Action time** | **instantaneous** | **durative** (start/end times, e.g. boiling water) |
| **Action cost** | none | costs on edges ⇒ plan metrics |
| **Who changes the world** | **agent only** (static) | **extraneous events** (shop timings, rain); **other agents** (collaborating, adversarial, competing for resources) |

Deterministic/stochastic and instantaneous/durative are **independent dimensions**. Even in the simplest domain planning is **PSPACE-complete** (polynomial space, exponential time).

### B2.3 STRIPS domains 🧪

STRIPS = *Stanford Research Institute Problem Solver* (SRI). A **STRIPS domain** is: finite and static; completely observable; changes happen **only through the agent's actions**; **one agent**; goals are **hard constraints on the final state only**; actions are **instantaneous and deterministic**; no explicit time. Modelled as a **state-transition system**

$$\Sigma=(S,\,A,\,\gamma),\qquad \gamma:S\times A\to S$$

($S$ finite set of states, $A$ finite set of actions, $\gamma(s,a)$ = resulting state when $a$ is applicable in $s$).

### B2.4 PDDL (Planning Domain Definition Language) 🧪

* Standardised languages (competitions are run with a fixed PDDL): you **describe** the domain instead of supplying `MoveGen`.
* **Components of a planning task:** **objects**; **predicates** (properties of objects); **initial state**; **goal specification** (a *partial* description — it covers many states); **operators/actions** (operator = generic, *pickup ?x*; **action = ground instance**, *pickup A*).

| Language | New features |
|---|---|
| PDDL 1.0 | STRIPS: instantaneous, deterministic, complete knowledge |
| (next) | **conditional effects** (book is in the office only *if* it is in the bag) |
| PDDL 2.1 | **numerical fluents** (fuel level), **plan metrics**, **durative actions** |
| PDDL 2.2 | **derived predicates** (consequences of effects, e.g. a block of ice cools the room), **timed initial literals** (exogenous events: shop opens at 9) |
| PDDL 3.0 | **trajectory constraints**, soft constraints |
| PDDL 3.1 | **object fluents** (functions returning objects) |

The course stays with the **STRIPS** subset (later relaxed to two cooperating arms, as two independent agents).

## B3. The blocks-world domain, progression

### B3.1 Predicates 🧪

| Predicate | Meaning |
|---|---|
| `on(X,Y)` | block $X$ is directly on block $Y$ |
| `ontable(X)` | $X$ is on the table |
| `clear(X)` | nothing is on $X$ |
| `holding(X)` | the (single) robot arm holds $X$ |
| `armempty` | the arm holds nothing |

Qualitative description: no sizes, unlimited table, blocks stack one on one, **one arm, one block at a time**. A state stores **only the true predicates** (negation by failure: a deleted predicate is false).

### B3.2 Operators 🧪

An operator has a **name**, **arguments**, **preconditions** $\text{pre}(o)$, **positive effects** $\text{eff}^+(o)$ (*add list*) and **negative effects** $\text{eff}^-(o)$ (*delete list*).

| Operator | Preconditions | Positive effects (add) | Negative effects (delete) |
|---|---|---|---|
| **unstack($X,Y$)** | `armempty`, `on(X,Y)`, `clear(X)` | `holding(X)`, `clear(Y)` | `armempty`, `on(X,Y)` |
| **pickup($X$)** | `armempty`, `ontable(X)`, `clear(X)` | `holding(X)` | `armempty`, `ontable(X)` |
| **putdown($X$)** | `holding(X)` | `ontable(X)`, `armempty` | `holding(X)` |
| **stack($X,Y$)** | `holding(X)`, `clear(Y)` | `on(X,Y)`, `armempty` | `holding(X)`, `clear(Y)` |

* `putdown` is the inverse of `pickup`; `stack` is the inverse of `unstack`.
* **Design choice** left open in the lecture: whether `clear(X)` is deleted when $X$ is picked up/unstacked and re-added when put down/stacked (harmless for one arm). My code deletes/adds `clear` consistently (✅).
* ⚠️ The lecture's slides omit the negative effect `holding(X)` for `stack`/`putdown` — it **must** be present.
* A **negative effect** is implemented by **deleting** the predicate from the state description; that is why `putdown` doesn't need "not on table" as a precondition.

### B3.3 Applicability, progression, plans 🧪

$$a\ \text{applicable in}\ s\iff \text{pre}(a)\subseteq s\qquad\qquad \gamma(s,a)=s'=\bigl(s\setminus\text{eff}^-(a)\bigr)\cup\text{eff}^+(a)$$

* **Plan** $\pi=\langle a_1,\dots,a_n\rangle$ (a sequence). $\pi$ is **applicable** in $s_0$ if there are states $s_1,\dots,s_n$ with $s_i=\gamma(s_{i-1},a_i)$ and each $a_i$ applicable in $s_{i-1}$; then $s_n=\gamma(s_0,\pi)$.
* $\pi$ is a **valid plan (solution)** for goal $G$ iff $\;G\subseteq\gamma(s_0,\pi)$.
* **Goal description** $G$ is a *partial* state description (a set of predicates); it stands for many goal states, just as a partial tour stands for many tours or a cluster for many strategies. Goal test = subset test.
* Worked example: `unstack(A,B)` is applicable (arm empty, `on(A,B)`, `clear(A)`); progression adds `holding(A)`, `clear(B)` and deletes `armempty`, `on(A,B)`.
* Lecture example: start with a large state; goal $\{\text{on}(G,A),\text{on}(B,J)\}$; optimal plan: move $A$ and $F$ out of the way (unstack A from B, unstack F from G…), unstack G from H, stack G on A, pick up/unstack B, stack B on J.

## B4. Forward vs backward state-space planning

### B4.1 Forward State-Space Planning (FSSP) 🧪

* Start at $s_0$; **applicable** actions generate successors (this is `MoveGen`); search with DFS/BFS/best-first/hill climbing using any of the earlier algorithms.
* The plan grows by **appending** actions to the **end**: $\pi\leftarrow\pi\,a$.
* **Sound:** progression always yields a **legal state**.
* **High branching factor:** the state is *completely* described, so many actions are applicable, most irrelevant to the goal (after `unstack A B` you may put $A$ back, on $C$, $F$, $J$, $K$, $P$, or on the table). Without a good heuristic it is expensive.

### B4.2 Backward State-Space Planning (BSSP) 🧪

* Start from the **goal description** $G$ (often small); consider only **relevant** actions.

$$a\ \text{relevant to}\ G\iff \text{eff}^+(a)\cap G\neq\emptyset\ \ \wedge\ \ \text{eff}^-(a)\cap G=\emptyset$$

* **Regression:** $\;G'=\gamma^{-1}(G,a)=\bigl(G\setminus\text{eff}^+(a)\bigr)\cup\text{pre}(a)$ (remove what the action achieves; add what it needs).
* The plan grows by **prepending** actions: $\pi\leftarrow a\,\pi$ (the last action is found first).
* A plan $\pi$ is relevant to $G_n$ if regressing over $a_n,\dots,a_1$ gives sub-goals $G_{n-1},\dots,G_0$; **terminate when $G_0\subseteq s_0$**.
* **Lower branching factor:** in the lecture's problem only two actions are relevant to $\{\text{on}(G,A),\text{on}(B,J)\}$: `stack(G,A)` and `stack(B,J)`. (Student's objection: the tree still branches; answer: *far less* than forward planning.)

### B4.3 The problem with BSSP 🧪

* Operators are designed for **progression** (built-in arrow of time), so **regression is not closed over the state space**: a regressed goal need not describe any legal state.
* **Example** (✅ code): $s_0$: A, B, C on the table. Goal $\{\text{on}(A,B),\text{on}(B,C)\}$.
  1. Relevant `stack(A,B)` ⇒ $G'=\{\text{on}(B,C),\text{holding}(A),\text{clear}(B)\}$.
  2. Relevant `stack(B,C)` ⇒ $G''$ contains **`holding(A)` and `holding(B)`** at the same time — impossible with one arm (`armempty` also appears). BSSP can't see this.
  3. Continue with `pickup(A)`, `pickup(B)` until the sub-goal is contained in $s_0$ ⇒ "plan" $\langle$pickup B, pickup A, stack B C, stack A B$\rangle$.
  4. **Check by progression:** after `pickup B` the arm is busy, so **`pickup A` is not applicable** ⇒ **invalid** (✅ `run_plan → None`).
* ⇒ BSSP needs an extra **validity check** by progression; if invalid, search for another plan. Consistency checking of regressed goals (e.g. the program *TIM*) is hard.
* Reordering the spurious plan's actions is a larger search (permutations ⇒ factorial).

### B4.4 FSSP vs BSSP summary 🧪

| | **Forward (FSSP)** | **Backward (BSSP)** |
|---|---|---|
| Starts at | start state $s_0$ (complete description) | goal description $G$ (partial) |
| Moves must be | **applicable** ($\text{pre}\subseteq s$) | **relevant** ($\text{eff}^+\cap G\neq\emptyset$, $\text{eff}^-\cap G=\emptyset$) |
| Transition | **progression** $s'=(s\setminus\text{eff}^-)\cup\text{eff}^+$ | **regression** $G'=(G\setminus\text{eff}^+)\cup\text{pre}$ |
| Plan built | by appending ($\pi a$) | by prepending ($a\pi$) |
| Termination | $G\subseteq s_n$ | $G_0\subseteq s_0$, then **check validity** |
| Branching factor | **high** (all applicable actions) | **low** (only relevant actions) |
| Soundness | **sound** (legal states) | **unsound** (spurious/inconsistent sub-goals) |

## B5. Goal Stack Planning and Sussman's anomaly

### B5.1 Idea 🧪

**Goal Stack Planning** keeps the best of both: **search backward** (goal-directed ⇒ low branching) but **build the plan forward** (an action is added to the plan only when it is *applicable* in the current state ⇒ no spurious states). It is a **linear planner**: split the compound goal into individual goals and solve them **one at a time, serially**; suited to domains where goals can be solved independently (cook three dishes one by one). It maintains a **stack** (goals + actions), the **current state** $s$ and the **plan** (initially empty).

### B5.2 Algorithm 🧪

```text
Goal-Stack-Planning(S, G, O)                  # start state, goal set, operators
  s ← S;  plan ← [];  stack ← []
  push_set(G)
  while stack not empty:
      x ← pop(stack)
      if x is an ACTION a:           plan ← plan ++ [a];   s ← γ(s, a)           # a is guaranteed applicable
      else if x is a COMPOUND goal:  if x ⊄ s: push_set(x)                       # re-attempt (goals may have been undone)
      else (x is a single goal g):
           if g ∈ s: continue                                                    # already true, nothing to do
           choose an action a relevant to g   (non-deterministic; backtrack in practice; failure if none)
           push(a);  push_set(pre(a))                                            # action first, then its preconditions on top

push_set(Goals):  push the compound goal (the whole set), then push the individual goals
                  (the LAST pushed is solved FIRST)
```

* The **compound goal** is pushed beneath the individual goals to **check at the end** that solving the parts independently still leaves the whole true (if not, it is pushed again).
* Because the stack is **LIFO**, the order in which you push the sub-goals is the *reverse* of the order in which they will be solved ⇒ **ordering heuristics** are possible.
* Popped actions are always applicable (their preconditions were solved first) ⇒ plans are **valid by construction**.

### B5.3 Worked example (right order) ✅

A, B, C on the table; goal $\{\text{on}(A,B),\text{on}(B,C)\}$. Push `on(A,B)` first and `on(B,C)` last so `on(B,C)` is **solved first**.

1. Pop `on(B,C)` (false) ⇒ push action `stack(B,C)` and its preconditions `holding(B)`, `clear(C)`.
2. Pop `clear(C)` ✓ (true). Pop `holding(B)` ✗ ⇒ push `pickup(B)` + its preconditions `ontable(B)`, `clear(B)`, `armempty` (all true).
3. Pop the preconditions (true), pop the action `pickup(B)` ⇒ **plan = [pickup B]**; state: holding B.
4. Pop `holding(B) ∧ clear(C)` ✓, pop `stack(B,C)` ⇒ **plan = [pickup B, stack B C]**.
5. Pop `on(A,B)` ✗ ⇒ `stack(A,B)`, preconditions `holding(A)`, `clear(B)` ⇒ `pickup(A)` …
6. Final plan: **pickup B, stack B C, pickup A, stack A B** — 4 steps, valid, optimal (✅ BFS optimum is 4).

### B5.4 Wrong goal order

Push order reversed (solve `on(A,B)` first): GSP stacks $A$ on $B$, then to achieve `on(B,C)` must **unstack A, put it down**, pick up B, stack on C — it **undoes the first goal** — then the compound goal fails and `on(A,B)` is attempted again.
Plan found (✅): *pickup A, stack A B, unstack A B, putdown A, pickup B, stack B C, pickup A, stack A B* = **8 steps** (valid but twice as long).

* **Goal ordering matters**: it may give longer plans or even **dead ends** (cooking: peel before chop; wrong order ⇒ backtracking).

### B5.5 Non-serialisable sub-goals — Sussman's anomaly 🧪

* Gerald Sussman showed that for some problems **no goal order** gives an optimal plan, because achieving one goal **undoes** the other and the solution needs **interleaving** of sub-goals. (Rubik's cube is similar: reaching the next layer disturbs the previous one.)
* **Sussman's anomaly:** start: **C on A**, B on the table, A on the table. Goal: **A on B, B on C**.

| Strategy | Result |
|---|---|
| Solve `on(B,C)` first | pick up B, stack on C ⇒ then `on(A,B)` needs B and C unstacked and A re-stacked ⇒ end with A on B but **C on the table** — goal not met; more work |
| Solve `on(A,B)` first | unstack C, put it down, pick up A, stack on B ⇒ then `on(B,C)` needs A unstacked, B stacked on C ⇒ **A not on B** — redo |
| **Optimal 6-step plan** | unstack C A · putdown C · pickup B · stack B C · pickup A · stack A B |

* The optimal plan needs to **stop working on `on(A,B)` in the middle (after C is on the table), achieve `on(B,C)`, then return** — GSP can't do this (it finishes one goal before starting the next).
* ✅ Code: forward BFS finds the **6-step** optimum; my GSP produced valid but longer plans (**10** or **14** steps depending on goal order — the exact length depends on the choice of relevant actions and precondition order).
* ⇒ Need planners that are **not linear**: **plan-space / partial-order planning**.

## B6. Plan-space (partial-order) planning

### B6.1 Idea 🧪

Search the **space of plans**, not states (like TSP branch & bound searching the space of tours: *refine the partial solution*). Any sequence of actions is a plan; the space of plans is **infinite** (pickup A, putdown A, pickup A, …). Plan-space planning (PSP) = **partial-order planning (POP)**; no commitment to the first or last action — an action just *occurs somewhere*, and orderings are added only when needed.

### B6.2 Partial plan = 4-tuple $\langle A,\,O,\,L,\,B\rangle$ 🧪

| Component | Meaning |
|---|---|
| $A$ | set of (partially instantiated) **actions** in the plan; variables written with `?` (e.g. `stack(A,?y)`) |
| $O$ | set of **ordering links** $A_i\prec A_j$ ("$A_i$ before $A_j$"); the partial plan is a directed graph |
| $L$ | set of **causal links** $A_i\xrightarrow{\,P\,}A_j$: $A_i$ has positive effect $P$ which is a precondition of $A_j$ ($A_i$ = *producer*, $A_j$ = *consumer*). Adding a causal link also adds the ordering link $A_i\prec A_j$ |
| $B$ | **binding constraints** on variables ($x=y$, $x\neq y$, $x\neq B$, $x\in\{\dots\}$) |

### B6.3 The initial plan $\pi_0$ 🧪

For a problem $(s_0=\{S_1..S_n\},\;G=\{G_1..G_k\},\;\text{operators})$:

* two dummy actions: **$A_0$** — no preconditions, **effects $=s_0$** (it *produces the start state*); **$A_\infty$** — **preconditions $=G$**, no effects;
* ordering $A_0\prec A_\infty$; no causal links; no binding constraints.
* $\pi_0$ is an "empty plan" standing for the **set of all plans** for the problem.

### B6.4 Flaws and solutions 🧪

A **solution plan** is a partial plan **without flaws**. Two kinds of flaw:

1. **Open goal:** a precondition $P$ of some action $A_p$ **not supported by a causal link**.
2. **Threat:** an action $A_t$ that can *possibly* destroy a causal link $A_i\xrightarrow{P}A_j$.

**Resolving an open goal $P$ of $A_p$** (two ways):

* use an **existing action** $A_e$ that produces $P$ and can consistently come before $A_p$ ⇒ add causal link $A_e\xrightarrow{P}A_p$ and ordering $A_e\prec A_p$ (extreme case: start = goal ⇒ only links from $A_0$ to $A_\infty$, no actions at all);
* otherwise **insert a new action** $A_{new}$ that produces $P$, add the causal link and the ordering (this is where real planning happens).

**Threat to $A_i\xrightarrow{P}A_j$** — it materialises when **all three** hold:

1. $A_t$ has an effect $\neg Q$ with $P$ **unifiable** with $Q$ (simplest case $Q=P$);
2. $A_t$ can come **after** $A_i$ ($A_i\prec A_t$ not excluded);
3. $A_t$ can come **before** $A_j$.

Eliminate it by removing **one** condition:

| Method | Action | Effect |
|---|---|---|
| **Separation** | add a binding constraint so $P$ and $Q$ **cannot unify** (e.g. $x\neq A$) | only when variables exist |
| **Promotion** | order $A_t\prec A_i$ — threat **before the producer** | adds an ordering link |
| **Demotion** | order $A_j\prec A_t$ — threat **after the consumer** | adds an ordering link |

Example in the lecture: `unstack(?x,A)` produces `clear(A)` consumed by `pickup(A)`; `stack(B,?y)` deletes `clear(?y)` ⇒ threat if $?y=A$ and it falls between them. Promotion: stack before unstack; demotion: pickup before stack; separation: $?y\neq A$.

### B6.5 Worked example (lecture) ✅

Start: **B on C**, C on the table, A on the table; `clear(A)`, `clear(B)`, `armempty`. Goal: **`ontable(B)`, `on(A,B)`** (C's position is irrelevant).

1. $\pi_0$: $A_0$ (effects = start state), $A_\infty$ (preconditions = goal). Open goals: `on(A,B)`, `ontable(B)`.
2. `on(A,B)`: no existing producer ⇒ **insert `stack(A,B)`** (only way); causal link `stack(A,B) –on(A,B)→ A∞`. (Missing negative effect `holding(A)` assumed.) Open goals now: `holding(A)`, `clear(B)`, `ontable(B)`.
3. `clear(B)`: true in the start ⇒ **link from $A_0$** (existing action).
4. `holding(A)`: insert **`pickup(A)`** (applicable in the start state; heuristic: prefer pickup to unstack); its preconditions link to $A_0$.
5. `ontable(B)`: insert **`putdown(B)`**; it needs `holding(B)` ⇒ insert **`unstack(B,C)`** (its preconditions are true in the start state, link to $A_0$).
6. No open goals remain. The lecture finds **three threats** (🔎 my reading of the transcript):
   * `stack(A,B)` deletes `clear(B)`, which `unstack(B,C)` needs (link from $A_0$);
   * `pickup(A)` deletes `armempty`, which `unstack(B,C)` needs (link from $A_0$);
   * `pickup(A)` also threatens the other link that supplies `armempty` (the arm is no longer empty) around `putdown(B)`.
7. Resolve (no variables ⇒ promotion/demotion only): add orderings **unstack(B,C) ≺ stack(A,B)**, **unstack(B,C) ≺ pickup(A)**, **putdown(B) ≺ pickup(A)**.
8. Result: a total order — **unstack(B,C) → putdown(B) → pickup(A) → stack(A,B)**, 4 steps.

✅ Code: of the $4!=24$ orderings of these four actions, **exactly one** is a valid plan, and it is the one the ordering links produce.

### B6.6 Remarks

* The domain-specific blocks-world solution (put all blocks on the table, then build the goal) is **not** domain-independent; the lecture uses blocks world only to illustrate.
* Each causal link must support **every** precondition of **every** action ($A_\infty$ included); a precondition without a link is an open goal.
* **The space of plans is infinite**, so POP need not terminate if there is no solution (no length bound) — a student's variation (only two columns allowed) changes the domain definition.
* Grey dotted lines = causal links (circle = producer end, square = consumer end); ordering links are drawn only where needed (transitive ones omitted).

## B9. Quiz-preparation tips

1. **Always check applicability by subset** (`pre ⊆ state`) before applying an action; apply by *delete negative effects, then add positive effects*.
2. **Regression:** delete the action's **positive** effects from the goal, then **add its preconditions**; test relevance first (non-empty add∩G, empty delete∩G). A regressed goal containing `holding(X)` and `holding(Y)` or `armempty` and `holding(...)` together is **inconsistent**.
3. BSSP answers must be followed by a **progression check** of the plan; show where it fails.
4. **GSP traces:** write the stack explicitly; remember **LIFO** — the *last pushed* goal is solved *first*; the **compound goal sits under its parts**; a popped action goes to the plan and the state is progressed.
5. If a goal is already **true in the current state**, just pop it. If an undone goal reappears, the compound goal check re-pushes it.
6. **Goal order:** for $\{\text{on}(A,B),\text{on}(B,C)\}$ solve **on(B,C) first** (push it last). The wrong order gives a longer (8-step) plan.
7. **Sussman:** neither order gives the 6-step plan; interleaving is needed ⇒ motivates POP.
8. **POP steps:** (i) list the open goals; (ii) for each, existing producer (causal link + order) or new action; (iii) list threats — check the **three conditions**; (iv) resolve with **promotion/demotion/separation**; (v) stop when no flaws.
9. Distinguish **ordering link** ($\prec$, any precedence) from **causal link** (producer–proposition–consumer, implies ordering).
10. Remember the **dummy actions** $A_0$ (produces the start state) and $A_\infty$ (consumes the goal).
11. ⚠️ Applicable (**forward**, preconditions in state) vs relevant (**backward**, effects intersect goal); progression is sound, regression is not.
12. ⚠️ **Open goal ≠ threat**: open goals are *missing* support; threats *break* existing support.

## B10. Self-test questions with answers

1. **What distinguishes planning from configuration problems?** Planning returns the **path/sequence of actions**; configuration returns just a satisfying state.
2. **List STRIPS assumptions.** Finite, static, completely observable, single agent, hard goals on final state, instantaneous deterministic actions.
3. **Apply `unstack(A,B)` to $s=\{\text{armempty},\text{on}(A,B),\text{clear}(A),\text{ontable}(B)\}$.** $s'=\{\text{ontable}(B),\text{holding}(A),\text{clear}(B)\}$ (with `clear(A)` deleted as in the code's convention).
4. **Is `stack(A,B)` relevant to $G=\{\text{on}(A,B),\text{clear}(B)\}$?** No: it adds `on(A,B)` but **deletes `clear(B)`**, which is in $G$ (relevance needs $\text{eff}^-\cap G=\emptyset$).
5. **Regress $G=\{\text{on}(A,B),\text{on}(B,C)\}$ over `stack(A,B)`.** $G'=\{\text{on}(B,C),\text{holding}(A),\text{clear}(B)\}$.
6. **Why is regression "not closed over the state space"?** A regressed goal may describe no legal state (e.g. holding A and holding B).
7. **Which has the higher branching factor, FSSP or BSSP, and why?** FSSP — complete state ⇒ many applicable but irrelevant actions.
8. **What does GSP combine?** Backward goal-directed search (low branching) with forward plan construction (valid plans).
9. **GSP wrong goal-order plan length for the 3-block problem?** 8 steps (vs 4).
10. **State Sussman's anomaly and the optimal plan length.** C on A, B on table; goal A on B, B on C; non-serialisable sub-goals; optimal plan is 6 steps.
11. **Components of a partial plan?** Actions $A$, ordering links $O$, causal links $L$, binding constraints $B$.
12. **What are the two actions in the initial plan?** $A_0$ (effects = start state) and $A_\infty$ (preconditions = goal).
13. **Two kinds of flaw and how to repair the first.** Open goals (add a causal link from an existing action, or insert a new action) and threats.
14. **Three threat resolutions.** Separation (bindings), promotion (threat before producer), demotion (threat after consumer).
15. **Number of valid orderings of the four POP-example actions?** Exactly 1 of the 24 permutations.
16. **Why may POP not terminate on an unsolvable problem?** The space of plans is infinite (e.g. pickup A, putdown A repeated).

    return (s - dele) | add if pre <= s else None
def regress(G, pre, add):                 # G' = (G \ add) U pre
