## 1. Big picture & lecture map

The course follows one storyline: **general, domain-independent search algorithms** into which you plug problem-specific functions (`MoveGen`, `GoalTest`, and later `h`).

| Lecture segment (transcript) | Core idea |
|---|---|
| A Tiny Example; Analysis of DFS and BFS | Same search tree, different exploration order; time/space/quality/completeness |
| Blind Search; General Search Algorithms | `OPEN`/`CLOSED`, generate-and-test, node pairs, list operators |
| Depth First Iterative Deepening | Linear space **and** shortest path; DFID-N vs DFID-C |
| Planning vs Configuration Problems; State Space Search | Path vs. goal state; water-jug, 8-puzzle, river crossing, map colouring, TSP |
| Algorithm Demos | Visual comparison of DFS / BFS / Best-First / A\* |
| Heuristic Search; Hill Climbing | `h(n)`, Best-First, gradient following, local maxima |
| Deterministic Local Search | Neighbourhood functions, VND, Best-Neighbour, Tabu |
| Solution Space Search | SAT and TSP as solution-space problems; savings/greedy/NN heuristics |
| Emergent Systems and ACO | Game of Life, fractals, ant colonies, pheromone |
| Iterated Hill Climbing; Stochastic Local Search | Random restarts, Random Walk, Simulated Annealing |
| Genetic Algorithms; Solving TSP using GAs | Selection, crossover, mutation; CX / PMX / OX |

**Two families of methods**

* **State-space (path-finding) search** — keep `OPEN`/`CLOSED`; the *path* matters (planning).
* **Solution-space (local) search** — each node is a *candidate solution*; the *state itself* is the answer (configuration problems such as SAT, N-Queens, TSP tours). Memory is O(1) or small.

## 2. Problem formulation

A search problem needs only:

| Component | Meaning |
|---|---|
| `S` | start state (conventionally named `S`; goal conventionally `G`) |
| `MoveGen(N)` | returns the **list** of neighbours of `N` (an *implicit* graph, generated on the fly) |
| `GoalTest(N)` | returns `true`/`false`; may describe the goal ("some jug has 4 litres") rather than name one state |
| `h(N)` (later) | heuristic estimate of distance-to-goal |

**State space vs. search space.** The *state space* is a graph (nodes may be reachable by many paths). The *search space* is the **tree** the algorithm unrolls from `S`; the same state can appear many times unless pruned with `CLOSED`.

**Problem types**

| Type | What is sought | Examples |
|---|---|---|
| **Planning** | A **path** (sequence of moves) | Water jugs (8-5-3), 8-puzzle, Man–Goat–Cabbage–Lion river crossing, blocks world |
| **Configuration** | A **state** satisfying a description | N-Queens, SAT, map colouring, TSP tour |

**Worked formulations from the lectures**

* **Three-jug (8, 5, 3 L):** state = triple, start `(8,0,0)`; goal `(4,4,0)` *or* "any jug holds 4" (a *described* goal terminates earlier). Moves are reversible pours.
* **8-puzzle:** 9!/2 reachable states — the graph splits into **two disconnected halves** (not every start reaches the goal).
* **River crossing:** state = two lists (left bank, right bank, boat); illegal states (lion with goat, goat with cabbage unattended) are filtered inside `MoveGen`.
* **Map colouring:** brute force → informed search → general search / constraint satisfaction.

## 3. List notation (cons, append, head, tail)

🧪 *The grader checks node order, so these operators must be second nature.*

| Notation | Meaning | Example |
|---|---|---|
| `[]` | empty list | |
| `x : L` | **cons** — put element `x` at the *head* of `L` | `3 : [2,1] = [3,2,1]` |
| `L1 ++ L2` | **append** — join two lists | `[o,u,t] ++ [r,u,n] = [o,u,t,r,u,n]` |
| `head L` / `tail L` | first element / the rest | `head [3,2,1]=3`, `tail [3,2,1]=[2,1]` |
| `first`, `second` … | components of a **tuple** (fixed size, may mix types) | `first (a,b,c) = a` |
| `_` | "don't care" placeholder in destructuring | `(N, _) ← nodePair` |
| `←` / `=` | assignment / equality test | |

⚠️ `:` takes **element + list**; `++` takes **list + list**. Lists hold any number of same-kind items; tuples hold a fixed number of items of possibly different kinds.

## 4. Simple search, OPEN and CLOSED

* **Generate-and-test:** generate a node, test it, stop when `GoalTest` is true.
* `OPEN` = generated but not yet inspected (the *frontier*, candidates). `CLOSED` = already inspected (*seen*).
* The key design question: **which node to pick from `OPEN`?** It decides speed, and sometimes whether a solution is found at all.

```text
Simple-Search-1(S)                      Simple-Search-2(S)
 OPEN ← {S}                              OPEN ← {S};  CLOSED ← {}
 while OPEN ≠ ∅                          while OPEN ≠ ∅
   pick some N from OPEN                   pick some N from OPEN
   OPEN ← OPEN − {N}                       OPEN ← OPEN − {N};  CLOSED ← CLOSED ∪ {N}
   if GoalTest(N): return N                if GoalTest(N): return N
   else OPEN ← OPEN ∪ MoveGen(N)           else OPEN ← OPEN ∪ (MoveGen(N) − CLOSED)
 return null                             return null
```

* Simple-Search-1 is **non-deterministic** and can cycle forever (S→A→S→B→S…) with `OPEN` growing.
* Simple-Search-2 adds `CLOSED` to stop revisiting nodes — this was the *primary* reason `CLOSED` was introduced.
* Both return only the **goal node**, not the **path**. To return a path, store **node pairs** `(node, parent)` and rebuild with `ReconstructPath`.
* Course convention from here on: **always pick the head of `OPEN`**; algorithms differ only in *where new nodes are inserted*.

## 5. DFS and BFS

### 5.1 Algorithms (Week 2 sheet) 🧪

```text
DFS(S)                                         BFS(S)  — identical except line 12
 1 OPEN ← (S, null) : []                        12  OPEN ← (tail OPEN) ++ newPairs      ← queue
 2 CLOSED ← empty list                          DFS 12: OPEN ← newPairs ++ (tail OPEN)  ← stack
 3 while OPEN is not empty
 4   nodePair ← head OPEN
 5   (N, _) ← nodePair
 6   if GoalTest(N) = TRUE
 7       return ReconstructPath(nodePair, CLOSED)
 8   else CLOSED ← nodePair : CLOSED            ← cons ⇒ CLOSED is newest-first
 9       neighbours ← MoveGen(N)
10       newNodes  ← RemoveSeen(neighbours, OPEN, CLOSED)
11       newPairs  ← MakePairs(newNodes, N)
12       OPEN ← newPairs ++ (tail OPEN)         (DFS)
13 return empty list
```

**Ancillary functions**

```text
MakePairs(nodeList, parent):  [] if empty, else (head nodeList, parent) : MakePairs(tail nodeList, parent)
RemoveSeen(nodeList, OPEN, CLOSED): drop every node that occurs in OPEN or in CLOSED (keeps MoveGen order)
ReconstructPath(nodePair, CLOSED): path ← node : [];  while parent ≠ null:
                                       path ← parent : path;  CLOSED ← SkipTo(parent, CLOSED);
                                       (_, parent) ← head CLOSED
```

### 5.2 Behaviour

| | DFS | BFS |
|---|---|---|
| `OPEN` is a … | **stack** (LIFO) – newest children first | **queue** (FIFO) – oldest first |
| Shape | dives to the boundary, then backtracks | level by level ("conservative") |
| Stays … | as far as possible from start | as close as possible to start |
| Direction sense | none – same behaviour wherever the goal is | none |

### 5.3 Trace on the lecture example (verified by code)

`MoveGen`: `S→[A,B,D]`, `A→[C,B,S]`, `B→[S,A,C]`, `C→[B,A]`, `D→[S,G]`. Goal `G`.

| Algorithm | Order of inspection | Path found |
|---|---|---|
| DFS | S, A, C, B, D, G | S, D, G |
| BFS | S, A, B, D, C, G | S, D, G |

Both generate the *same search tree* (with `RemoveSeen` on OPEN and CLOSED) but explore it in different orders. Final `CLOSED` (newest first): DFS `[D,B,C,A,S]`; BFS `[C,D,B,A,S]`.

### 5.4 Three variants of "what to prune" (lecture "Tiny Example")

| Case | Rule when adding children | Consequence |
|---|---|---|
| 1 | skip nodes in **OPEN or CLOSED** (course version) | smallest search tree |
| 2 | skip only nodes in **CLOSED** | duplicates on OPEN allowed; trees of DFS and BFS differ (e.g. BFS may re-add `C` when inspecting `B`) |
| 3 | no `RemoveSeen` at all | **DFS loops forever** (S→A→C→B→S…); BFS still reaches the goal (here on the 11th inspection) |

### 5.5 Complexity analysis (branching factor $b$, goal depth $d$)

Time ≈ number of nodes inspected (= size of CLOSED); space ≈ size of OPEN.

| Quantity | DFS | BFS |
|---|---|---|
| Goal at far-left of tree | $d+1$ nodes | $\displaystyle\sum_{i=0}^{d-1} b^i$ (+1) nodes — all shallower levels first |
| Goal at far-right | whole tree | whole tree |
| Whole tree | $\displaystyle\frac{b^{d+1}-1}{b-1}$ | same |
| Average | $\approx b^{d}/2$ | larger by factor $\displaystyle\frac{b+1}{b-1}$ |
| Time | $O(b^d)$ exponential | $O(b^d)$ exponential |
| Space (size of OPEN) | **linear**: each level adds $b-1$ siblings $\Rightarrow (b-1)\,d$ | **exponential**: $\approx b^{d}$ (multiplies by $b$ each level) |
| Shortest path? | **No** | **Yes** (inspects paths of increasing length) |
| Complete? | Only if no infinite branch (can get lost) | **Yes** if a finite-length path exists |

* For $b=10$: BFS inspects only $11/9\approx1.22\times$ more than DFS ⇒ **larger $b$ ⇒ time complexities converge.**
* Frontier: DFS grows linearly, BFS exponentially. "Completeness" means *systematically exploring the whole space*; if **no** path exists in an infinite space, both run forever.
* Lecture advice: infinite space ⇒ prefer BFS (guarantee); finite space ⇒ real trade-off between space (DFS) and solution quality (BFS). DFS can keep **one board copy** and undo moves (huge saving for e.g. 25 000-Queens).

## 6. DFID (depth-first iterative deepening)

**Goal:** BFS's shortest-path guarantee with DFS's linear space.

### 6.1 Depth-bounded DFS and the DFID driver 🧪

* Nodes become **triples** `(node, parent, depth)`; start `(S, null, 0)`.
* Children are generated only if `depth < depthBound`; each child gets `depth + 1`.
* `count` = total number of nodes **added to OPEN** during one bounded run (`count ← count + length newPairs`).

```text
DFID(S)                                       DB-DFS(S, depthBound)
 1 count ← −1                                  10 count ← 0
 2 path ← empty list                           11 OPEN ← (S, null, 0) : []
 3 depthBound ← 0                              12 CLOSED ← empty list
 4 repeat                                      13 while OPEN is not empty
 5   previousCount ← count                     14   nodePair ← head OPEN;  (N,_,depth) ← nodePair
 6   (count, path) ← DB-DFS(S, depthBound)     16   if GoalTest(N): return (count, ReconstructPath(nodePair, CLOSED))
 7   depthBound ← depthBound + 1               18   else CLOSED ← nodePair : CLOSED
 8 until (path ≠ empty) or (previousCount = count)   19     if depth < depthBound
 9 return path                                 20       neighbours ← MoveGen(N)
                                               21       newNodes ← RemoveSeen(neighbours, OPEN, CLOSED)   ← DFID-N
                                               21'      newNodes ← RemoveSeen(neighbours, OPEN, [])       ← DFID-C
                                               22       newPairs ← MakePairs(newNodes, N, depth+1)
                                               23       OPEN ← newPairs ++ tail OPEN;   24 count ← count + length newPairs
                                               25     else OPEN ← tail OPEN
                                               26 return (count, empty list)
```

**Termination test `previousCount = count`:** if an entire deeper iteration added **no** new nodes (finite space, goal absent), stop; otherwise DFID would loop forever. Starting `count` at $-1$ guarantees the first comparison cannot trigger.

### 6.2 DFID-N vs DFID-C 🧪

| | **DFID-N** | **DFID-C** |
|---|---|---|
| `RemoveSeen` line 21 | `(neighbours, OPEN, CLOSED)` | `(neighbours, OPEN, [])` |
| Opens | only **new** nodes (not in OPEN/CLOSED); never reopens | new nodes **and re-opens** nodes that are in CLOSED but not in OPEN |
| Shortest path guaranteed? | **No** | **Yes** |
| `CLOSED` used for | pruning + path reconstruction | **path reconstruction only** |

**Why DFID-N can fail (the lecture's "Siddharth Sagar" question).** At bound $k$ a node may be reached on a *long* path first and put on CLOSED; on a later, shorter route it is **not regenerated**, so the shortest path is missed. Verified counterexample (directed graph, found by the script in §19):

```text
S:[A,B]  A:[S,C]  B:[D,C]  C:[D,A,X]  D:[A,C,G]  G:[A,B]    goal = G
BFS (shortest):  S → B → D → G      (3 edges)
DFID-N returns:  S → A → C → D → G  (4 edges)   ← D already CLOSED via C, so B's child D is never generated
DFID-C returns:  3 edges (shortest)
```

**Path reconstruction in DFID-C** needs depth to pick the *right* occurrence of the parent in CLOSED: `SkipTo(parent, CLOSED, depth−1)` matches `(parent, _, depth)`.
(Alternative idea mentioned: store the whole path in each node.)

### 6.3 Cost and trade-offs

* DFID re-inspects internal nodes each round. If BFS sees $L$ nodes (the leaf level), DFID sees $L + I$, with $I$ internal nodes and, for a full tree, $L=(b-1)I+1$.

$$\frac{\text{nodes (DFID)}}{\text{nodes (BFS)}}\;\approx\;\frac{b}{b-1}\qquad(b=10\Rightarrow\approx 10\%\text{ extra})$$

* So DFID: **time $O(b^d)$, space linear, shortest path** (DFID-C semantics) — the "best of both worlds".
* For configuration problems (N-Queens, SAT, colouring) the path is irrelevant, so DFID mainly helps by finding *shallower* solutions earlier.
* Games: engines run depth-bounded DFS to a "play depth" and deepen while time remains (*anytime* behaviour).
* Weakness shared with all blind search: **no sense of direction** — behaviour is identical wherever the goal lies (Hydra metaphor: each node inspected spawns several more). That motivates heuristics.

## 7. Heuristic search: Best-First Search

**Idea.** Blind search ignores where the goal is. A **heuristic** $h(n)$ is a *static, cheap-to-compute estimate* of how close $n$ is to the goal (like a blindfolded agent feeling the gradient of a valley). Heuristics are **estimates** — they "can see the map but cannot see the river".

**Heuristics from the lectures**

| Problem | $h_1$ | $h_2$ |
|---|---|---|
| 8-puzzle | **Hamming**: number of tiles out of place | **Manhattan**: sum over tiles of grid-distance to goal square (example in lecture: Hamming 4 vs Manhattan 5; Manhattan is the more informed one) |
| Map / grid | Euclidean (straight-line) distance | Manhattan distance (grid hops) |
| Blocks world (maximise) | +1 per block on the correct block/table | +n for a block on a correct structure of $n$ blocks, −n otherwise (more informed: $h_1$ had a local maximum, $h_2$ had only the global maximum) |

⚠️ Maximisation and minimisation are the same problem: negate $h$. "Better" means *lower* for distance-like $h$ and *higher* for score-like $h$.

### 7.1 Algorithm (Week 3 sheet) 🧪

```text
Best-First-Search(S)
 1 OPEN ← (S, null, h(S)) : []
 2 CLOSED ← empty list
 3 while OPEN is not empty
 4   nodePair ← head OPEN;  (N, _, _) ← nodePair
 6   if GoalTest(N) = TRUE: return ReconstructPath(nodePair, CLOSED)
 8   else CLOSED ← nodePair : CLOSED
 9     neighbours ← MoveGen(N)
10     newNodes  ← RemoveSeen(neighbours, OPEN, CLOSED)
11     newPairs  ← MakePairs(newNodes, N)
12     OPEN ← sort_h ( newPairs ++ tail OPEN )        ← sort best→worst h
13 return empty list
```

**Tie-breaking rule (Week 3 sheet) 🧪:** when several nodes share the same best cost, **sort them alphabetically by node label and take from the head.** No partial marks if you ignore this.

**Properties**

| Property | Best-First |
|---|---|
| Complete | Yes (finite graph, with CLOSED) |
| Optimal | **No** – "quality" is whatever the heuristic leads to |
| Time/space | Exponential in the worst case; with a perfect $h$ frontier would be linear, in practice not |
| Behaviour | Has a *sense of direction*; drives straight toward the goal, can be fooled (e.g. nodes near the goal across a river) |
| Self-reinforcing | With several goals, it commits to whichever is closest |

Demo take-aways: DFS has the same path regardless of goal; BFS explores a ball around the start; Best-First goes almost straight; A\* explores far less than BFS while still returning the shortest path.

## 8. Local search: Hill Climbing, neighbourhoods, VND, Beam

### 8.1 Hill Climbing 🧪

Keep **only the current node** (no `OPEN`, no `CLOSED`): "burn the bridges".

```text
Hill-Climbing(S)
1 N ← S
2 do  bestEver ← N
3     N ← head sort_h MoveGen(bestEver)       ← best neighbour (ties: alphabetical label)
4 while h(N) is better than h(bestEver)
5 return bestEver                              ← NOTE: returns bestEver, not N
```

| Property | Value |
|---|---|
| Space | **Constant** $O(1)$ (vs exponential for BFS/Best-First) |
| Time | One neighbourhood evaluation per step; stops at first non-improving step |
| Complete / optimal | **No** – gets stuck at **local optima** |
| Nature | Greedy, steepest-ascent, local; the heuristic + neighbourhood define the **terrain** |

**Terrain features:** *local maximum* (no better neighbour, not global), *global maximum*, **plateau** (all neighbours equal), **ridge** (in the lecture's SAT landscape: an edge joining two nodes of equal value; HC never moves along it), multiple best neighbours (dashed arrows → tie, pick by rule).
Sanity check on 8-puzzle solution paths: along a *valid* solution $h$ is **not monotone** (e.g. moving tile 8 out of place raises Hamming distance temporarily), so a good heuristic still has local traps.

### 8.2 Neighbourhood functions

For a bit-string of length $n$ (e.g. SAT), $N_i$ = "flip exactly $i$ bits":

$$|N_i| = \binom{n}{i},\qquad |N_{1,2}| = \binom n1+\binom n2,\qquad |N_{1\ldots n}| = 2^n-1\ \ (\text{whole space} \Rightarrow \text{brute force})$$

For $n=5$: $|N_1|=5,\ |N_2|=10,\ |N_{12}|=15$ (lecture values).

* **Denser neighbourhood** ⇒ fewer local optima (more likely a better neighbour exists) **but** each step must generate/inspect more neighbours (the "constant" space/time grows).
* "Constant space" HC is only constant for a fixed neighbourhood.

### 8.3 Variable Neighbourhood Descent (VND) 🧪

Order neighbourhoods **sparse → dense**; run HC with each in turn, keep the result.

```text
Variable-Neighbourhood-Descent(S)
1 MoveGenList ← MoveGen₁ : MoveGen₂ : … : MoveGenₙ : []
2 bestNode ← S
3 while MoveGenList is not empty
4    bestNode ← Hill-Climbing(bestNode, head MoveGenList)
5    MoveGenList ← tail MoveGenList
6 return bestNode
```

Hope: most climbing is done cheaply with sparse functions; dense ones are used for a few final steps. How many neighbourhoods you can afford depends on problem size (10-variable SAT: brute force is fine; 50 variables: not).

### 8.4 Beam Search (Week 3/6 sheet version) 🧪

Keeps the $w$ best nodes of each **layer**; `MoveGen` over a list **preserves duplicates**.

```text
Beam-Search(S, w)
1 OPEN ← S : []
2 N ← S
3 do  bestEver ← N
4     if OPEN contains goal node: return that goal node
6     else neighbours ← Move-Gen(OPEN)              ← ++ of MoveGen(X) for X in OPEN
7          OPEN ← take w (sort_h neighbours)
8          N ← head OPEN                            ← best in new layer
9 while h(N) is better than h(bestEver)
10 return bestEver
```

* `take n LIST` returns at most $n$ items from the front: `take 3 [o,u,t,r,u,n] = [o,u,t]`, `take 3 [a,t] = [a,t]`, `take 3 [] = []`.
* Width $w=1$ behaves like hill climbing; larger $w$ explores more. This version stops when the best of the new layer is no better than the best so far ("assignment friendly, prevents infinite loops").
* ⚠️ Because duplicates are kept, the same node can occupy several beam slots.

## 9. Escaping local optima: Best-Neighbour and Tabu Search

**Exploitation** = follow the heuristic; **exploration** = deliberately leave the gradient. Escaping local optima means loosening the grip of $h$.

### 9.1 Best-Neighbour Search

Always move to the **best neighbour even if it is worse**; remember the best node ever seen; stop on a termination condition (e.g. number of moves).

```text
Best-Neighbour-Search(S)
1 N ← S;  bestEver ← S
3 until some termination condition
4     N ← best Move-Gen(N)
5     if N is better than bestEver:  bestEver ← N
7 return bestEver
```

⚠️ It can **cycle** (go back to the node it just left) — which tabu search prevents.

### 9.2 Tabu Search 🧪

* `M(i)` — **memory/tenure** array: number of moves for which flipping bit $i$ is still forbidden (`tabu(i)=yes` iff `M(i) > 0`). Tabu tenure `tt` is a parameter.
* `F(i)` — **frequency** array: how often bit $i$ has been changed; used to **penalise** overused moves (long-term diversification).
* **Aspiration criterion:** a tabu move is allowed if it beats the best value ever seen.

```text
Tabu-Search-2(tt)
 1 F ← array of N zeros;  M ← array of N zeros
 3 currentNode ← random node;  bestEver ← currentNode
 5 while some termination criteria
 6    Generate-Neighbours                    (neighbour(i) = Change(currentNode,i); value(i)=eval(...); tabu(i))
 7    Find-Best-n-Best-Allowed-Neighbours    (bestValue/bestIndex over ALL; bestAllowedValue/bestAllowedIndex over non-tabu)
 8    if bestValue better than eval(bestEver):      Move-To(bestIndex)          ← aspiration
10    else if bestAllowedValue not worse than eval(currentNode):  Move-To(bestAllowedIndex)  ← improvement
12    else Find-Best-Allowed-With-Penalty:  value(i) ← value(i) − Penalty(F(i)) for non-tabu i;  Move-To(bestAllowedIndex)  ← diversify
14 return bestEver

Move-To(index)
35 currentNode ← neighbour(index)
36 if value(index) better than eval(bestEver):  bestEver ← currentNode
38 for i ← 1..N if M(i) > 0:  M(i) ← M(i) − 1          ← age all tenures first
40 M(index) ← tt                                          ← then make the changed bit tabu
41 F(index) ← F(index) + 1
```

⚠️ Order inside `Move-To`: **decrement** existing tenures, **then** set `M(index) ← tt`, then bump `F`.
Name: from Tongan *tapu* ("taboo"). Tenure example in lecture: tt = 2 on a 7-bit problem. Choosing the neighbourhood and `tt` is *part of algorithm design*.
Lecture SAT landscape: values range 3–6; **two global maxima (6)** and **three local maxima (5)**; tabu started on a local maximum walks along ridges and escapes.

## 10. Solution-space problems: SAT and TSP

**Solution-space search:** every node is a *candidate solution*; `GoalTest` can score any node; `MoveGen` defines neighbours (a *neighbourhood function*). (Planning can also be done here as *plan-space planning*.)

### 10.1 SAT

* Boolean formula in **CNF** (AND of clauses, each clause an OR of literals); must make **every clause** true.
* Candidate = bit-string of $n$ variables ⇒ space size $2^n$; SAT is **NP-complete**.
* Heuristic: **number of satisfied clauses** (lecture example: values 3–6 with 6 clauses).
* As the ratio $m/n$ (clauses/variables) grows, a random formula is less likely to be satisfiable.
* Brute force is hopeless for large $n$ ⇒ local search.

### 10.2 TSP

* Representation: a **permutation** of cities (add missing edges with very high cost).
* Number of distinct tours: naïvely $N!$, but rotations and reversals are the same tour:

$$\text{number of tours}=\frac{(N-1)!}{2}\qquad(N=5: 12;\ N=10: 181\,440)$$

* **NP-hard**, and an answer cannot easily be verified as optimal.
* A tour: every city has exactly **one incoming and one outgoing edge** (no forks, no premature loops).
* Neighbourhoods: swap two cities in the path representation; **$k$-edge exchange** — choose $k$ edges in $\binom nk$ ways (e.g. $\binom n3$ for three edges); denser ⇒ costlier.

**Constructive heuristics (Week 4 sheet) 🧪**

```text
Nearest-Neighbour:  start at some city; repeat: go to nearest unvisited neighbour that does not close the loop prematurely or create a fork
Greedy:             sort all edges by cost; repeat: add the shortest available edge that does not close the loop prematurely or create a fork
Savings(n = base city):
   build N−1 sub-tours of length 2 anchored at n
   savings(a,b) = cost(n,a) + cost(n,b) − cost(a,b)     for non-base a<b   (b > a ignores inverse edge)
   sort savingsList in DESCENDING order of savings
   for each (a,b,_): if edges (n,a) and (n,b) lie in two DIFFERENT tours → remove (n,a),(n,b); insert (a,b)   (merge)
   return the final tour
```

Savings example (verified): base distances $c(n,1)=2,\ c(n,2)=4,\ c(n,3)=6$; $c(1,2)=3,\ c(1,3)=5,\ c(2,3)=4$ ⇒ savings $(1,2)=3,\ (1,3)=3,\ (2,3)=6$ ⇒ merge $(2,3)$ first.

## 11. Stochastic local search

Deterministic local search always makes the same moves from a start; **randomisation** adds exploration. Always **track bestEver**, because the walk may wander away from it.

```text
Random-Walk(N)                                    Iterated-Hill-Climbing(N)
 node ← random candidate / start node              bestNode ← random candidate solution
 bestNode ← node                                   repeat N times
 repeat N times                                      currentBest ← Hill-Climbing(new random candidate)
   node ← random node from MoveGen(node)             if h(currentBest) better than h(bestNode): bestNode ← currentBest
   if h(node) better than h(bestNode): bestNode←node return bestNode
 return bestNode
```

Iterated HC = *random restarts*: if each HC run is cheap and different starts fall in different basins, you probably hit a good one.

### 11.1 Simulated Annealing 🧪🔎

Accept a neighbour with probability given by the **sigmoid** (maximisation form):

$$\Delta E = \text{eval(neighbour)} - \text{eval(node)},\qquad
P(\text{move}) = \frac{1}{1+e^{-\Delta E/T}}$$

```text
Simulated-Annealing
 node ← random/start;  bestNode ← node;  T ← some large value
 for time ← 1 to number-of-epochs
     while some termination criteria (M random moves at this T)
         neighbour ← Random-Neighbour(node)
         ΔE ← eval(neighbour) − eval(node)
         if random(0,1) < 1/(1+e^(−ΔE/T)):  node ← neighbour
         if eval(node) better than eval(bestNode): bestNode ← node
     T ← Cooling-Function(T, time)
 return bestNode
```

**Behaviour of the sigmoid** (values computed by the script in §19):

| $\Delta E \;\backslash\; T$ | −4 | −2 | −1 | 0 | +1 | +2 | +4 |
|---|---|---|---|---|---|---|---|
| $T=4$ | 0.269 | 0.378 | 0.438 | **0.5** | 0.562 | 0.622 | 0.731 |
| $T=2$ | 0.119 | 0.269 | 0.378 | **0.5** | 0.622 | 0.731 | 0.881 |
| $T=1$ | 0.018 | 0.119 | 0.269 | **0.5** | 0.731 | 0.881 | 0.982 |
| $T=0.5$ | 0.000 | 0.018 | 0.119 | **0.5** | 0.881 | 0.982 | 1.000 |
| $T=0.25$ | 0.000 | 0.000 | 0.018 | **0.5** | 0.982 | 1.000 | 1.000 |

* **High $T$:** curve is flat near 0.5 ⇒ almost a random walk (**exploration**).
* **Low $T$:** curve becomes a step function ⇒ accepts almost only improvements (**exploitation**, like HC).
* $\Delta E = 0$ ⇒ probability **exactly 0.5** (moves between equal nodes half the time).
* Even bad moves are accepted with non-zero probability, which is how it climbs out of local maxima.
* Random number $r\in[0,1)$ is compared with $P$: a bigger $P$ ⇒ bigger range of $r$ accepted. The neighbour is **chosen randomly** (not all neighbours are evaluated) — cheaper per move than HC.
* ⚠️ For a *minimisation* problem the sign of $\Delta E$ flips (or use $e^{-(\text{increase})/T}$).
* Cooling schedule, epochs and $M$ are design choices; starting $T$ is "some large value".

## 12. Genetic Algorithms

Population-based search inspired by natural selection (Darwin) and genetics (artificial selection instead of natural).

```text
Genetic-Algorithm()
1 P ← create N candidate solutions                       ← initial population
2 repeat
3     compute fitness value for each member of P
4     S ← with probability proportional to fitness, randomly select N members from P   (roulette wheel; clones)
5     offspring ← partition S into two halves, randomly mate and crossover members → N offspring
6     with a low probability mutate a few offspring
7     replace k weakest members of P with k strongest offspring
8 until some termination criteria
9 return the best member of P
```

**Operators**

| Operator | What it does |
|---|---|
| **Selection / reproduction** | Roulette wheel: sector size ∝ fitness; spin $N$ times (implementable with one random number, same trick as SA). Fitter members get more clones; weak ones may vanish |
| **Crossover** | Mix genes of two parents (e.g. single-point: swap tails). Any gene-mixing operator will do |
| **Mutation** | Randomly change a few genes with low probability — usually harmful, occasionally valuable; restores lost genes |

**Selection formulas** 🔎

$$p_i=\frac{f_i}{\sum_j f_j},\qquad \mathbb E[\text{ number of copies of }i]=N\,p_i=\frac{f_i}{\bar f}$$

**Goldberg's tiny example** ($f(x)=x^2$ on 5-bit strings; verified numbers): population $x=13,24,8,19$ ⇒ fitness $169,576,64,361$, sum $1170$, average $292.5$, expected copies $0.58,\ 1.97,\ 0.22,\ 1.23$ (the lecture quotes the 1.23; the fittest member gets ≈2 copies, the weakest may vanish). After selection + crossover, fitness values like $144,\ 625,\ 729$ appear and the **average fitness rises** (≈293 → ≈439 in Goldberg's book; the transcript's figure is garbled 🔎).

**Diversity matters:** if a gene (bit position) is identical in all members, crossover can never recreate the missing value — only mutation can. A large, diverse population is critical.
Compare with hill climbing: GA holds a **population**, explores many basins in parallel.

### 12.1 GA for TSP — why plain crossover fails

Single-point crossover on tours produces **repeated and missing cities** (invalid tours). Special representations/operators are needed:

| Representation / operator | Idea | Gotchas |
|---|---|---|
| **Path representation** (list of cities in visiting order) | natural; use CX / PMX / OX | one tour has many representations (rotations, reversal) |
| **Cycle Crossover (CX)** | identify *cycles* of positions between parents; alternate which parent supplies each cycle | preserves absolute **position** of each city |
| **Partially Mapped (PMX)** | copy a segment from parent 1 into child; fill the rest using the *partial map* defined by the segment; resolve conflicts through the map | always yields a **valid** tour |
| **Order Crossover (OX)** | copy a sub-tour from one parent; fill remaining cities in the **order** they appear in the other parent | preserves relative **order** |
| **Adjacency representation** (`city i → successor`) + **alternating-edges crossover** | child takes edges alternately from parents | can create **sub-cycles / repeated cities** ⇒ must repair; not every adjacency list is a valid tour (but the representation can still express every tour) |
| **Ordinal representation** | each gene = index into a shrinking list of remaining cities (delete a city when used, so later indices decrement) | then ordinary single-point crossover is valid |

Fitness for TSP = tour length (minimise) or its inverse/negation.

## 13. Emergent systems and Ant Colony Optimization

**Emergence:** complex global behaviour from many simple local rules (no central controller).

* **Conway's Game of Life** 🔎: per cell, count live neighbours — live cell with <2 live neighbours dies; with 2–3 survives; >3 dies; a dead cell with exactly 3 becomes alive. Yields *gliders* (a shape that reappears shifted after 4 steps) and "guns" that emit them.
* **Fractals:** infinitely complex, self-similar patterns from repeating a simple process.
* Brains: ~$10^{11}$ neurons, each connected to ~$10^4$ others; **artificial life / evolved creatures** (Karl Sims); Steve Grand: persistence of patterns; Dawkins: evolution as cumulative selection of random variation.
* **Stigmergy / pheromone:** each ant lays a pheromone trail and probabilistically follows stronger trails ⇒ colonies find **shortest paths** (even around a new obstacle: shorter routes get reinforced faster).

### 13.1 ACO for TSP (Dorigo, 1992)

Procedure: place $M$ ants on the $N$ cities; each ant builds a tour with a **stochastic greedy** rule; each ant lays pheromone only on edges of **its own** tour; keep the best tour found; repeat. A tour takes $N$ time steps to build.

$$p_{ij}^{k}(t)=\frac{[\tau_{ij}(t)]^{\alpha}\,[\eta_{ij}]^{\beta}}{\displaystyle\sum_{l\in\text{allowed}_k}[\tau_{il}(t)]^{\alpha}\,[\eta_{il}]^{\beta}},\qquad \eta_{ij}=\frac1{d_{ij}}\ \text{(visibility)}$$

$$\tau_{ij}\leftarrow(1-\rho)\,\tau_{ij}+\Delta\tau_{ij},\qquad \Delta\tau_{ij}=\sum_{k}\Delta\tau^{k}_{ij},\quad \Delta\tau^{k}_{ij}=\frac{Q}{L_k}\ \text{if ant }k\text{ used edge }(i,j)$$

🔎 These are the standard Ant-System forms; the lecture states them verbally: probability ∝ (pheromone) × (visibility = closeness), pheromone **evaporates** at some rate each cycle, and better (shorter) tours deposit more. Conventions for $\rho$ (evaporation vs persistence) differ between texts — check which one your course sheet uses.

* Ant Colony Optimization belongs to **swarm optimisation**; works for problems reducible to graph search.

## 14. Week 5-6 slide algorithms (A-star, BnB, WA-star, SMGS)

*Not covered by the Week 2–4 transcript; summarised from the algorithm sheets you attached.*

**A\*(S)** — $f(n)=g(n)+h(n)$; `g` defaults to $+\infty$, `parent(S)=null`, `g(S)=0`.

```text
while OPEN not empty
   N ← remove node with lowest f from OPEN;  add N to CLOSED
   if GoalTest(N): return Reconstruct-Path(N)
   for each M in Move-Gen(N):
       if g(M) > g(N) + k(N,M):                       ← found a cheaper way to M
           parent(M) ← N;  g(M) ← g(N)+k(N,M);  f(M) ← g(M)+h(M)
           if M in OPEN: continue
           else if M in CLOSED: Propagate-Improvement(M)     ← re-parent descendants recursively
           else add M to OPEN                                  ← M is new
```

`Propagate-Improvement(M)`: for each $X$ in `Move-Gen(M)`, if $g(X) > g(M)+k(M,X)$ then update parent, $g$, $f$; if $X\in$ CLOSED recurse.

**BnB(S)** — `OPEN` holds `(path, g)` pairs (priority queue); expand the cheapest *path*.

```text
OPEN ← (S:[], 0) : []
while OPEN not empty: (path,g) ← head OPEN; N ← head path
    if GoalTest(N): return reverse path
    else newPaths ← [ (M:path, g+k(N,M)) for M in Move-Gen(N) ]      ← each consed in front
         OPEN ← sort_g(newPaths ++ tail OPEN)
```
`BnB-2` prevents cyclic expansions (S…A…S…A…). **Generalised BnB:** start with all possible solutions; repeat *refine the least-estimated-cost solution* until the cheapest is fully refined.

**WA\*(S, w):** A\* with $f(M)=g(M)+w\cdot h(M)$ (and the same in `Propagate-Improvement`).

**SMGS (Sparse-Memory Graph Search):** memory-optimised A\*; OPEN unchanged; CLOSED is split into **BOUNDARY** (unrestricted memory) and **KERNEL** (fixed size, periodically cleared). With $I$ = interior nodes whose lowest-cost path is known and $\text{Pred}(k)$ = predecessors of $k$:

$$\text{KERNEL}(I)=\{k\in I \mid \forall p\,(p\in \text{Pred}(k)\Rightarrow p\in I)\},\qquad \text{BOUNDARY}(I)=I\setminus\text{KERNEL}(I)$$

## 17. Quiz-preparation tips

### Node order is everything (the sheets warn: *no partial marks*)

1. **Always pick `head OPEN`.** Only the insertion position differs:
   * DFS: `newPairs ++ tail OPEN` (new nodes in **front**, in `MoveGen` order)
   * BFS: `tail OPEN ++ newPairs` (new nodes at the **back**)
   * Best-First: `sort_h(newPairs ++ tail OPEN)`
2. **`CLOSED` is cons-ed** (`nodePair : CLOSED`) so when printed it is **newest first** — the reverse of inspection order. ⚠️ Check whether a question asks for *order of inspection* or *contents of CLOSED*.
3. **Preserve `MoveGen` order** inside `RemoveSeen` and `MakePairs`; then DFS puts the *first* neighbour at the head and inspects it first.
4. **`RemoveSeen` checks both OPEN and CLOSED.** A node already waiting in OPEN is *not* added again — so in BFS it keeps its earlier (shallower) position; in DFS it stays deep in the stack even if a new route finds it.
5. **Goal test happens when a node is *removed* from OPEN (inspected)**, not when generated. That's why both DFS and BFS inspect `C` before `G` in the tiny example.
6. **Tie-breaking:** equal-cost nodes → sort by **node label alphabetically**, take from the head (Best-First, Hill Climbing, Beam, BnB, A\* selections).
7. **Hill Climbing returns `bestEver`**, and compares the *new* best neighbour to the *old* node; with equal $h$ it **stops** ("better than" is strict).
8. **Beam search:** collect neighbours of **all** beam nodes (duplicates kept) → sort by $h$ → `take w` → stop if new head is not better than bestEver. Check goal *before* expanding.
9. **DFID:** reset `OPEN`, `CLOSED`, `count` at every depth bound; `count` adds `length newPairs`; `depth < depthBound` gates expansion; N vs C differ *only* in line 21.
10. **Tabu:** per step — (a) compute all neighbours, (b) best overall vs best allowed, (c) aspiration → improvement → penalty case, (d) decrement tenures, set `M(index)=tt`, increment `F(index)`.

### Concept checklists

* **Four evaluation criteria** for any search algorithm: *time, space, quality of solution, completeness*.
* **Why CLOSED?** to avoid loops/rework; **why DFID-C doesn't use it for pruning** → to guarantee shortest path.
* **Local search = O(1) memory, but incomplete**; population/stochastic methods trade guarantees for escaping local optima.
* **Exploration vs exploitation** vocabulary: SA ($T$), Tabu (tenure, frequency penalty), GA (mutation, diversity), ACO (evaporation).
* **Density trade-off:** denser neighbourhood ⇒ fewer local optima, more work per step.
* **TSP:** NN and Greedy are constructive; Savings merges tours by descending savings; **always check "no fork, no premature loop"**.
* **Heuristic ≠ truth:** it is an estimate; Manhattan ≥ Hamming (more informed); more informed heuristics remove local maxima (blocks-world $h_2$).

### Frequent traps ⚠️

* Mixing up `:` (cons) and `++` (append).
* Writing DFS order for BFS and vice-versa when `RemoveSeen` blocks re-adding.
* Counting depth from 1 instead of 0 (start node is depth 0; DFID starts with `depthBound = 0`).
* Forgetting the extra $-1$/`previousCount` logic (first DFID iteration cannot stop).
* Using $N!$ instead of $(N-1)!/2$ for symmetric TSP tours.
* SA: wrong sign of $\Delta E$ (maximisation vs minimisation) or forgetting that equal values give $0.5$.
* GA-for-TSP: proposing single-point crossover on permutations.
* Claiming DFS/DFID-N find shortest paths (they don't); claiming BFS needs linear space (it doesn't).

## 18. Self-test questions with answers

1. **DFS vs BFS — which line differs, and how?** Line 12: `newPairs ++ tail OPEN` (stack) vs `tail OPEN ++ newPairs` (queue).
2. **Space of DFS vs BFS for $b=3$, goal depth 4?** DFS OPEN grows by $b-1=2$ per level ⇒ ≈8; BFS frontier reaches $3^4=81$.
3. **Ratio of nodes BFS/DFS for $b=10$?** $11/9\approx1.22$.
4. **Why can DFID-N miss the shortest path?** Because a node reached first on a longer path stays in CLOSED and is not regenerated on the shorter path; DFID-C passes `[]` instead of `CLOSED`.
5. **Extra cost of DFID over BFS for $b=10$?** ≈ $b/(b-1)=1.11$, i.e. ~10 %.
6. **What does `previousCount = count` detect?** An iteration that added no nodes ⇒ the finite space is exhausted with no goal.
7. **Hill climbing — space and completeness?** $O(1)$ space; incomplete (local maxima, plateaus, ridges).
8. **SA: $\Delta E=0$ and $T=4$?** $P=0.5$. **$\Delta E=+2$, $T=1$?** $0.881$.
9. **How many tours for 6 cities?** $(6-1)!/2=60$.
10. **Savings: which pair is merged first?** The pair with the largest $c(n,a)+c(n,b)-c(a,b)$.
11. **GA: fitnesses $169,576,64,361$ — expected copies of the second?** $576/292.5\approx1.97$.
12. **Why is a gene missing from the whole population dangerous?** Crossover only recombines existing genes; only mutation can restore it.
13. **Beam search with $w=1$ resembles…?** Hill climbing (keeps one best node per layer).
14. **Tabu: when is a tabu move allowed?** If it beats the best value ever seen (aspiration criterion).
